### Lexical details

Fresh import calls `index_text` 5,848 times (52.21/session), and `terms`
8,440 times (75.36/session). Their cumulative shares, 33.49% and 18.75%, overlap.
The initial identifier-boundary regex search executes 5,848 times and consumes
7.90% self time. It is already regex C, but a certified literal implementation
of that fixed ASCII boundary predicate could avoid general regex machinery.
It is a distinct opportunity from eliminating Python bytecode and requires
exact predicate tests plus fallback for customized patterns.

`unicodedata.normalize` is already C (12,288 calls, 6.87% fresh-import self).
Preserve its whole-string normalization, canonical reordering, and current
Unicode database rather than substituting an approximate hand-built table.
Custom callable identities, subclass inputs, callback ordering and mutations
must retain the Python path. The per-character excerpt fold has a different
contract from whole-string term normalization and cannot be merged casually.

### Excerpt details

The existing native source fold accounts for 3.98% of total recall time (702
calls). Native literal matching is 0.67% (1,659 calls), and native evidence-unit
scanning is 0.11% (1,659 calls). Those functions are already in C.
The remaining score generator is invoked 122,094 times (242.25/query); its
self share is 0.55%. `math.fsum` is called 16,803 times and consumes 1.44%
cumulatively, including generator/logarithm work. These numbers overlap the
12.27% excerpt total.

An excerpt translation must preserve non-overlapping matches, the 40-match cap
per query term, duplicate and empty terms, Unicode code-point coordinates,
source maps and `bisect` boundaries. Preserve Counter insertion/deletion order,
`math.log1p`, `math.fsum`, floating placement, lexicographic score comparison and
the final tie-breaking start. Ordinary `sum`, altered rounding, or a different
window selection rule would exceed a language-only translation.

### Segmentation and retrieval details

Grouping must preserve the order of similarity/follow-up checks, maximum four
turns, minimum/maximum sizes, paragraph-cut preference, label/newline spelling,
headline truncation, original message indices and continuation coordinates.
These determine source references and page IDs. The unchanged-import profile
does not authorize skipping segmentation before hash comparison: that would
change execution/exception behavior beyond this task's translation boundary.

Candidate processing must retain the exact 2:1 route formula, title multiplier,
novelty calculations, finite-value validation, dictionary iteration and stable
sorting. Current-state grouping must remain scoped to task/project/session;
later unrelated mentions must not become authoritative updates. Database calls
and snapshot boundaries stay in Python unless an equally exact design is
separately demonstrated. SQL/native self time is 50.09% of the profiled recall.

## Benefit limits and next evidence

Eliminating only the measured project-Python self time entirely would yield
an illustrative 1.31x recall or 1.26x fresh-import speedup on this *instrumented*
workload. This is neither a forecast nor a universal ceiling: opaque C work,
profiler overhead, and native specialization change the relevant fractions.
It shows why adding overlapping cumulative shares or promising a severalfold
whole-system gain would be unjustified.

This small in-memory development corpus excludes disk/WAL/fsync costs, locks,
connection startup, MCP transport, token budgeting, semantic models, public
conversations and larger scales. Native candidates still need differential
tests and fixed native-vs-native uninstrumented measurements before acceptance.
No performance improvement is claimed by this profile alone.
