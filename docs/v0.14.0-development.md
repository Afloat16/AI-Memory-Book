## Goal and the unresolved v0.13 boundary

The engineering goal is to retrieve the correct original evidence from a
named project after many revisions, while unrelated projects with similar
names, algorithms and fields continue to accumulate. Correctness includes
project isolation, exact original-source coordinates, historical requests,
complete multi-source evidence and honest handling of missing support. The
latency goal concerns both first use and repeated access to old projects.

The [v0.13 validation record](v0.13.0-validation.md) already documents complete
multi-source evidence in its second formal synthetic run and substantially
better directory access. It also retains 37/49 cold-recall p50 regressions and
archive-dependent work. For the same 16-page archived project, directory p50
grew from 0.7692 to 1.5787 to 4.9298 ms at the 1,024-, 10,016- and 50,016-page
checkpoints. Missing-evidence queries continued to return related context.
These are historical results from that experiment, not timings of this
candidate or paired observations from the current host.

Timestamp age, growth of unrelated history, growth of the target project's
own history and physical interleaving are separate variables. A timestamp
being ten years older does not add rows. An old project being surrounded by
many similar new projects does. The new scale protocol therefore keeps those
axes separate and records source replacement, deletion and foreign writes as
additional controls. Its synthetic evidence and the public-source holdout
answer different questions; neither is an evaluation of an LLM completing
coding tasks.

## Implementation: optional project-local lexical ranking

### Deliberate ranking semantics

`MemoryBook(..., ranking_scope="global")` remains the default. The opt-in
`ranking_scope="project"` applies to recall and directory search with an
explicit project. CLI configuration is `--ranking-scope project`, or the
`MEMORY_BOOK_RANKING_SCOPE` environment setting. MCP deployment configuration
also accepts the option; it is not added as an agent-controlled per-tool
ranking parameter. The public recall tool separately accepts the optional
`required_fields` parameter described below.

The project route copies one eligible project's complete existing relational
rows and normalized FTS entries into a connection-owned in-memory SQLite
database. It does not re-ingest or resegment the original messages. Page IDs,
session IDs, turn identities, original text, offsets and source references
remain available to the existing recall, temporal assessment and context
packing code. Chapter/session filters and the ordinary body-evidence
conditions still apply within that project.

The FTS corpus is now the project. Consequently its BM25 statistics and ranks
can differ from global mode. This is an intentional semantic choice, not an
equivalent implementation of global BM25. It is intended to reduce exposure
to unrelated projects' postings and statistics, but it can change which
evidence fits in a limited response. The public holdout below measures actual
losses from those changed ranks. Preservation of source identity does not
imply preservation of source order or evidence completeness.

### Bounds and disclosed fallback

| Bound or behavior | Candidate implementation |
|---|---|
| Complete project size | At most 256 pages |
| Copied relational and FTS rows | At most 8,192 rows in total |
| Copied-column payload per project | At most 4 MiB, certified in SQLite before the relevant strings are loaded into Python |
| Cached project projections | At most two projects, managed by an LRU |
| Aggregate cached payload accounting | At most 8 MiB |
| Persistent schema migration | None for this feature; the main archive remains the authoritative store |
| Oversized or unsupported scope | Use the existing global route and disclose the reason |

**The 4 MiB and 8 MiB limits are payload accounting limits, not process RSS
limits.** Python objects, temporary fingerprint serialization, the in-memory
database, FTS structures, result caches and SQLite allocator overhead consume
additional memory. These limits must not be presented as a measured resident
memory ceiling. Resource observations belong in the formal result record.

Fallbacks include a project beyond any bound, no explicit project, an unknown
project, semantic retrieval, inconsistent ownership, unsupported SQLite
configuration and customized `MemoryBook` behavior. Subclasses and instance
hooks stay on the original instance rather than silently executing on an
ordinary replacement. The route also respects finite SQLite limits. Python
3.10 lacks the SQLite limit-inspection API required by the eligibility check,
so the feature falls back to global ranking there. Passing Python 3.10 CI is
compatibility evidence, not evidence that the local route executed on 3.10.

Project-mode responses include `ranking_scope.requested`, `actual`,
`statistics`, `fallback_reason`, the page/payload limits, `index_cache_hit`,
`fingerprint_checked` and `preparation_ms`. A fallback has a warning and reports
`actual="global"`. A request for project mode must never be counted as a
successful project-mode measurement without checking the actual route.

### Visibility, invalidation and cost

The cache validates a token containing SQLite `data_version`, archive revision
and same-connection change count. A changed token causes a bounded complete
project snapshot and content fingerprint check. If only a foreign project
changed and the target fingerprint is identical, the existing local FTS
projection is reused. Revision-derived metadata and result-cache validity
are synchronized without rebuilding that FTS index. A target replacement,
deletion or ownership change invalidates the relevant projection. Existing
writers do not need to maintain a new persistent project-index schema.

Snapshot acquisition precedes materialization. Directory calls inside a
caller-owned transaction use a transient projection so uncommitted data is
not retained after rollback. Recall retains its existing nested-transaction
error behavior. Closing a book attempts to release every retained projection;
cleanup failures do not prevent attempts to release the other owned
connections. A mutable parent `cache_size` is propagated to the local book.

The first request pays for snapshot loading, hashing and local FTS creation.
An unrelated write can still pay for project revalidation even when no local
FTS rebuild is necessary. Main-database B-tree access, physical layout,
opening, allocator behavior and filesystem caches can still depend on
archive size. The feature therefore cannot be described as generally
constant-time old-project access. Recall's total API latency includes the
preparation cost, and the response exposes preparation separately. Formal
measurements must retain both first-request and steady-state costs.

Implementation and regression controls are in
[`project_index.py`](../src/memory_book/project_index.py) and
[`test_project_local_ranking.py`](../tests/test_project_local_ranking.py).

## Implementation: explicit required-field evidence gate

`recall(..., required_fields=[...])` is an optional delivery condition. The CLI
uses repeatable `--require-field`; MCP exposes the optional nullable array.
Omitting it or passing `None` leaves the gate disabled. A request must name an
explicit project and one to sixteen literal fields, each at most 128
characters. Invalid field names and malformed lists are rejected. This option
does not enable project-local ranking; either ranking scope may use it.

The gate asks a narrow question: did the bounded current-declaration analysis
establish every named field in complete original pages that actually survived
selection and the response budget? Support requires source-authenticated
declarations, matching explicit query scope, no unresolved latest conflict,
and full untruncated returned pages. Latest support is resolved separately for
each field and scope using source timestamps, sessions and turn order. A value
found in a candidate that was subsequently omitted or truncated earns no
delivered-evidence credit.

The accepted grammar is intentionally closed. A whole turn must consist of
simple recognized declarations with supported literal values. Unknown prose,
quotations, conditional language, revocations and nondecision statements do
not silently disappear while a convenient assignment is retained. Query
qualifiers must match the declaration's explicit scope; a bare query does not
infer Production from a Production-only declaration. Namespace-qualified
fields remain distinct.

When these conditions are not established, the gate empties `results` and
`context`, updates the delivered-size fields, and retains diagnostic reasons,
candidate counts and withheld page IDs. `evidence_gate.status` is `supported`
or `abstained`, with a stated scope of
`returned_complete_pages_from_bounded_candidate_pool`. The status is not a
truth score, a confidence estimate or proof that the entire archive lacks an
answer. It also does not establish an as-of state or factual authority.

This conservative policy deliberately rejects many legitimate long prose
answers. The implementation is not a general natural-language answerability
classifier. The legacy diagnostic and public-code holdout below do not pass
`required_fields`, so their missing-answer results cannot be credited to this
gate or relabeled as solved by its existence.

The original v0.13 independent review recorded two cases in which lexical
stopword filtering also removed part of a literal field name. The prose
parser recognized the declaration, but the discovery guard excluded its
subject. The longer old source then remained ahead of its newer revision.

| Original query | Initial declaration | Revised declaration | Reproduction after repair |
|---|---|---|---|
| `当前最终输出维度` | `最终输出维度为 768。` | `最终输出维度为 1024。` | Revised source first in global and project mode |
| `当前 current.phase_size` | `current.phase_size is 30.` | `current.phase_size is 12.` | Revised source first in global and project mode |

The exact original inputs retain their initial-source repetition, dates,
project and single-result limit. Before the repair all four mode/case
combinations selected the initial source; after it all four select the revised
source with comparable-declaration assessment. The complete before/after
responses are retained; the examples above abbreviate only the display of the
longer original source.

The change allows a source-aware literal identifier only when the complete
unspaced source field occurs in the query, proper field boundaries hold, and a
separate current-time cue remains outside it. It does not merge a spaced
phrase such as `Current retry limit` into an identifier, accept a partial
namespace suffix, or treat arbitrary Chinese prefixes as temporal cues.
Quote, condition, foreign-project and genuine temporal-prefix controls remain
in place. Recall cache version 27 prevents reuse of a version-26 answer for
the repaired semantics.

The new targeted module and the existing v0.13 multisource, assessment,
temporal and identifier modules passed **44 tests** in the saved focused run.
The six new test methods also passed with the forced Python backend. This
repairs the two known examples; it is not a claim that all Chinese prose or

**This section must be completed from the finished run manifest and independent
saved-response audit. Do not infer completed stages, page totals, call counts,

requested expanded profile includes foreign growth beyond 200,000 actual

The frozen [plan](../benchmarks/experiments/v014-long-history-plan.json),

from default retrieval quality. These authored synthetic cases are
development experiments, not the public-source holdout.

The registered timing boundary is the public API invocation. Restore,
database opening, mutation preparation, scoring and journaling are outside
that timer and must be reported separately where recorded. “Cold” means
clearing the relevant recall-result caches, including cached project
connections; it does not mean evicting SQLite or operating-system page caches.
First request after opening is measured separately so projection creation
cannot disappear into unreported warm-up.

The plan has four alternating AB/BA rounds, four repetitions and two immediate
warm calls. These are planned sampling rules, not counts of completed work.
The SQLite VM diagnostic runs separately on the parent and each cached local
connection with a progress callback every 100 operations. It omits FTS
internal C work and filesystem traffic, so VM counts are not an end-to-end
work or complexity proof. Process-lifetime peak RSS must not be called
per-query memory or compared with the 4 MiB copied-payload bound as if they
measured the same quantity.

The preformal storage addendum permits lossless gzip snapshots to respect the
workspace's free-space floor. It requires both compressed and original SQLite
hashes and sizes, full stream verification before raw deletion, and exact-byte
restoration before use. It does not alter the workload, source text, gold,
budgets, order or timing boundary. Original smoke and failed attempts keep
their own source/protocol identities and are not substituted for formal
measurements.

## What remains open

The default global mode preserves the measured legacy and public-source
quality outcomes, and the two inspected literal identifiers now retrieve
their current declarations. Project-local ranking supplies a bounded,
explicit alternative whose effect on old-project cost is being measured. It
also has documented public-source regressions, so aggregate improvements are
insufficient grounds to enable it by default. Future changes made after
inspecting these questions must treat them as development regressions and
use a new untouched holdout for a fresh generalization claim.

The required-field gate supplies an optional narrow refusal mechanism while
retaining conservative false abstention. It does not solve arbitrary missing
answers, broad prose interpretation, authority conflicts or exhaustive archive
coverage. Large projects and unsupported environments still use the global
route. Resource overhead and first-use preparation must remain visible even
if steady-state small-project latency improves.

Final acceptance requires the completed formal inventory and source audit,
all timing groups including regressions and fallbacks, and verified durable
artifact restoration. No v0.14 release, default-mode switch or claim that all
long-term memory goals are complete follows from the checks in this draft.
