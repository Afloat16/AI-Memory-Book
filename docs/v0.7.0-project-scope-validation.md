# v0.7.0 project-scope validation

Status at this review checkpoint: **the project-scope diagnostic, native engineering regression and hosted browser job are complete; the initial full suite and complete hosted CI run failed, and their corrected reruns and release gates are not yet accepted.** This document records completed observations and retains unsuccessful attempts. It does not announce a v0.7.0 release.

The implementation adds optional project assertions to chapter, section and original-page reads, and lets an operator bind an MCP connection to one exact project. It addresses carrying a wrong project or an old page ID between similar engineering tasks. The caller still chooses the project; the mechanism does not infer the user's intended project and is not user authorization.

## 3. Independent interface and client review

The read-only review covered `store.py`, `scope.py`, MCP, CLI, HTTP/reader wiring and the completed client/setup binding changes. In the reviewed paths, chapter/section/page scope is checked in the database query; an unavailable or foreign ID does not trigger a global retry. Project and session conditions are combined during recall, including when different projects use the same session name.

Two reproducible issues found during review were fixed before the runtime freeze:

1. **Bound `browse_book` still required a tool argument.** Its original MCP input schema rejected `browse_book({})`, contradicting the bound connection's omission behavior. The argument is now optional; a bound call inherits the project. An unbound call still requires a project and raises a clear `ValueError` when it is omitted. Both outcomes were independently reproduced through the MCP SDK.
2. **HTTP `project=` silently selected global recall.** The previous `or None` converted an explicit empty query parameter into omission. The candidate now returns HTTP 400 for an empty project. Completely omitting the parameter retains global behavior, and a nonempty unknown project returns an empty recall result. This is an intentional compatibility change for explicit empty HTTP scope, not an unchanged interface.

The exact scope rules are:

| Request | Behavior |
| --- | --- |
| Bound MCP recall or evidence/directory read omits `project` | Inherit the connection's exact bound ID |
| Bound MCP supplies another project | Reject before opening the database |
| Bound MCP supplies an empty or invalid project argument | Reject argument validation |
| Bound MCP `remember_session` | Require an explicit matching `payload.project`; do not fill it silently |
| Unbound MCP recall/chapter/section/page read omits `project` | Keep global compatibility behavior |
| Unbound MCP `browse_book` omits `project` | Raise a clear required-project error |
| HTTP recall omits `project` | Keep global behavior |
| HTTP recall supplies `project=` | HTTP 400 |
| HTTP recall supplies a nonempty unknown project | Empty results; no global fallback |
| Scoped chapter/section/page read uses an ID from another project | Treat the ID as unavailable |
| Setup refresh omits a new `--mcp-project` | Preserve an existing managed binding |
| Setup supplies `--clear-mcp-project` | Explicitly remove the binding |

Independent runtime probes replaced the `MemoryBook` constructor with a failure sentinel and confirmed that conflicting scopes for all five scoped MCP tools, plus foreign/missing-project bound writes, were rejected before that constructor ran. The store and real interface regressions cover foreign/stale IDs, unknown projects, same-name sessions and unbound controls. A bound unknown project is not silently replaced by an existing project.

For `claude-code`, `codex`, `cursor`, `gemini`, `opencode` and `copilot-cli`, an independent temporary-config check generated argv with a project ID containing a leading hyphen, Chinese characters, spaces and a quote. The real CLI parser recovered the exact ID and `--allow-write`. Repeated setup without a new scope kept the binding with `changed=False`, and removal still recognized the managed entry. Setup did not create a database. Capture `--project` and connection `--mcp-project` remain separate settings.

These direct probes were observed during review; they were not a browser session or another counted benchmark cohort. The source review found no remaining reproducible blocker within those paths. **An MCP connection binding is not an ACL and does not bind a separate HTTP server or other direct database access.** Browser request wiring was inspected, but local UI execution was blocked as recorded below.

## 7. Reproduction commands

Run from a complete checkout containing the two published source commits. Use Python 3.10+ with SQLite FTS5; the recorded local replays used Python 3.12.14 and SQLite 3.53.1. Choose a fresh output directory so saved evidence is never overwritten. The scope and native character-budget diagnostics below do not need a model API or optional embedding dependencies.

```bash
mkdir -p .artifacts
scope_replay_dir="$(mktemp -d "$PWD/.artifacts/project-scope-replay.XXXXXX")"
mkdir -p "$scope_replay_dir/baseline-source" "$scope_replay_dir/candidate-source"
git archive 0572e65e198503f55ad4117619606b17a4c67540 src/memory_book \
  | tar -x -C "$scope_replay_dir/baseline-source"
git archive cf51473e841a3a38df7c7c857cf51e0e14eb1861 \
  src/memory_book benchmarks/project_scope_eval.py benchmarks/engineering_workflow.py \
  | tar -x -C "$scope_replay_dir/candidate-source"

PYTHONPATH="$scope_replay_dir/baseline-source/src" python \
  "$scope_replay_dir/candidate-source/benchmarks/project_scope_eval.py" \
  --output "$scope_replay_dir/baseline"
PYTHONPATH="$scope_replay_dir/candidate-source/src" python \
  "$scope_replay_dir/candidate-source/benchmarks/project_scope_eval.py" \
  --output "$scope_replay_dir/candidate" \
  --compare-baseline "$scope_replay_dir/baseline/report.json"

PYTHONPATH="$scope_replay_dir/baseline-source/src" python \
  "$scope_replay_dir/candidate-source/benchmarks/engineering_workflow.py" \
  --output "$scope_replay_dir/native-baseline" --budget-chars 1200 2400 \
  --repeats 1 --noise-per-step 2

  --root "$scope_replay_dir" --output "$scope_replay_dir/native-audit.json"
```
