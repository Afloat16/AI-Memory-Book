## User priorities and open goals

Accuracy and complete original evidence take precedence over speed. Similar
engineering projects must remain explicitly isolated, including historical
reads, source replacement and reused project/session/task labels. A fixed old
project should not incur growing retrieval work merely because unrelated
engineering histories grow elsewhere in the archive.

The previous release improved multi-source coverage and directory speed, but
did not achieve archive-size-independent old-project access. For an unchanged
16-page archived target, v0.13 current cold recall p50 rose from 10.516 to
13.689 to 25.743 ms at 1,024 / 10,016 / 50,016 total pages. Directory p50 rose
from 0.7692 to 1.5787 to 4.9298 ms. Cold means a cleared result cache, not an
operating-system cold boot. Missing-answer questions also still returned
context. These are retained v0.13 measurements, not new v0.14 results.

## Evidence and implementation rules

1. Keep the frozen v0.13 workload, runner, gold, protocol and all original
   results unchanged. New experiments use separate v0.14 files and attempt
   directories. Retain failures, adverse results and interrupted attempts.
2. Commit and remotely save the new protocol and evaluator before executing
   its formal quality or performance queries. Evaluator integrity checks are
   separate from formal retrieval measurements.
3. Separate timestamp age, foreign-history growth, own-history growth,
   interleaved layout, source replacement/deletion and cross-connection
   invalidation. Baseline and candidate use exact clean source identities,
   the same host and independently restored source archives.
4. Report first index construction, process open/first request, result-cache
   cold and warm queries, foreign writes, ingestion cost, storage and memory
   separately. SQLite VM progress counts do not measure all internal FTS C
   work and must not replace wall-clock measurements.
5. Any project-local ranking changes must be explicit. Global BM25 statistics
   currently make foreign writes a ranking dependency; reusing a result solely
   because its project rows are unchanged is not automatically correct.
6. Preserve exact project/source coordinates, replacement and deletion
   semantics, caller snapshots, rollback behavior and supported old archives.
   Derived indexes must have a safe, measured rebuild path.
7. Do not suppress relevant context through a tuned confidence threshold to
   make missing-answer fixtures look correct. Separate evidence availability,
   unsupported fields, conflicts and model answer accuracy.
8. No claim of a real-production holdout, constant-time access, full external
   product comparison or universal superiority without the relevant evidence.
9. Commit as `Afloat <ShuffleMonkey@163.com>` and verify that GitHub resolves
   both author and committer to `Afloat16` before updating remote refs.
