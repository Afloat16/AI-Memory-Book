# 长期算法工程记忆：实验与优化协议

本项目面向这样的工作：工程师长期维护多个相似项目，在不同会话和客户端间切换，
需要 AI 找回有效证据、理解当前约束，尽快交付经过验证的代码。
首要目标是 **time to correct patch（首次正确补丁所需时间）** 和 **tested success（经测试验证的成功率）**。
更快的查询、更少的 token、更多的检索命中，都是需要通过工程结果验证的中间指标。

本文是实验设计与后续实现协议，不是全面领先声明。建议门槛不是实测结果，也不改写已有发布门槛。
本轮实际结果、源码身份、运行命令和限制集中在 [engineering-memory-results.md](engineering-memory-results.md)。
历史检索与开源组件实验继续保留各自的 [版本和边界](../benchmarks/README.md)。

## 1. 当前可验证范围

本轮新增工程场景实验采用 **synthetic fixed-consumer**：合成历史、确定性消费者、可执行算法检查。
计划覆盖八个相似工程项目，即四类算法各两个项目，并在每个阶段仅摄取已经出现的历史前缀。
对照包含无记忆、按项目限定的扁平 FTS、Book 和预算内最近历史；实际完成情况以结果文件为准。
这能检查记忆是否使一个固定消费者选到适用的工程规则，并观察检索和上下文开销。
它不调用真实编码 LLM，不测开放式补丁生成，也不等价于真实工程师数周使用的效果。

运行入口（完整参数与本轮实测命令以结果文件为准）：

```bash
PYTHONPATH=src python -m benchmarks.engineering_workflow \
  --output .artifacts/engineering-memory-development \
  --repeats 3 --budget-chars 1200 2400
```

字符预算不能称为 tokenizer 的精确 token 预算；本机计时也不能替代真实 MCP 或 Agent 的端到端计时。
`--output` 是新实验目录，包含数据、逐例原始响应、JSON 和 Markdown 报告；不覆盖已有结果。
固定消费者不能看到答案标签、期望规则 ID 或隐藏断言；这些只属于评测器。
这里的消费者已知算法 family、允许的配置策略与 `key=value` 格式，只测显式策略恢复及应用。
它执行手写算法变体（包括固定小向量的数据分组），不是模型自主实现算法。
最近历史基线没有 top-5 限制且使用更短的引用头，适合作为实用策略对照，不能据此推断相同检索算法的速度优劣。
本轮暴露的同会话旧规则压过新规则问题，应通过定向回归检查与完整场景复跑验证。
这种修复的结论限定为相应检索行为；历史问题仍须允许返回旧时点的有效证据。

## 2. 实验矩阵

每类任务包含三种证据状态：历史经验有效、历史经验已过时、没有足够历史证据。
三个状态分别检验收益、错误复用与拒答，不能只采集“记忆一定有帮助”的问题。

| 工作情景 | 应保留的历史 | 关键扰动 | 工程验收 |
|---|---|---|---|
| 长间隔恢复项目 | 决策理由、当前阻塞、下一步 | 多会话与大量无关操作 | 正确恢复任务并通过功能检查 |
| 数值算法修复 | 输入约束、精度、边界案例 | 同名函数的不同语义、旧实现 | 数值误差和隐藏边界测试 |
| 训练与评估复现 | 数据版本、划分、seed、指标定义 | 数据泄漏修复、指标口径变化 | 指定协议下复现与无泄漏检查 |
| 依赖与 API 升级 | 环境锁文件、兼容性决定 | 分支差异、接口更名、回滚 | 当前环境中的编译与回归测试 |
| 性能回归定位 | 历史剖析、否定实验、硬件条件 | 硬件或输入规模变化 | 正确性不退化并达性能约束 |
| 相似项目切换 | 可复用经验及适用条件 | 同报错异根因、同配置异约束 | 有效迁移收益与错误迁移率 |
| 知识更新与冲突 | 原决定、修订、来源及时间 | 同会话多轮修正、延迟到达记录 | 当前与历史查询分别正确 |
| 缺证据与失败恢复 | 已知事实、待验证假设 | 文档缺失、检查失败、中断重启 | 识别缺口并完成必要验证 |

历史长度按会话数、事件数、原始 token 数、真实时间跨度分别记录。
把短数据复制多次只能模拟规模干扰，不能称为真实长期使用；两类来源分开报告。
对每个方法报告全部预算与任务类别，保留变差项目、失败调用和超时。

## 3. 两层评估与主指标

### A. 记忆子系统

| 指标 | 定义与限制 |
|---|---|
| 证据召回 / 完整证据率 | 必需证据是否进入最终交给消费者的上下文；搜索结果有而预算中没有，不能算成功 |
| 当前规则适用率 | 返回的结论是否适用于查询时点、项目、分支和环境；仅“更近”不足以成立 |
| 过时证据注入率 | 当前任务上下文中出现被取代且未标注失效的证据比例 |
| 错误跨项目迁移率 | 不满足目的项目条件的经验被实际采用的比例；同时报告有效迁移召回 |
| 来源支持率 | 引用能定位，且内容支持结论；存在 URL 或哈希不等于结论有依据 |
| 拒答与缺口识别 | 不可答任务是否要求验证；同时检查可答任务被错误拒绝的比例 |
| 性能与成本 | 查询 P50/P95、摄取、更新、验证、压缩、存储与完整响应负载 |

### B. 真实 Agent 工程任务（后续接入，当前未实现）

`tested_success` 要求在固定环境中同时通过任务隐藏测试、必要的已有回归测试和约束检查。
补丁格式有效、模型声称完成、可见测试通过，都不能单独替代这个判断。
`time_to_correct_patch` 从接收任务开始，到首次提交一个经评测器确认正确的候选补丁结束。
记录模型请求、工具、检索、额外读取、编译与验证各阶段耗时，以及实际总墙钟时间。

预算截止仍未正确完成的任务必须计失败，不能从时间表中删除。
同时报告完成率、完成时间曲线，以及截止时间内的受限平均完成时间。
在统一截止时间 τ 下，可用成功任务的完成时间、失败任务的 τ 计算该受限指标；
它描述预算内表现，不估计失败任务在无限时间下的实际完成时间。
只对成功样本算中位数可作为辅助值，必须标明样本选择和对应成功率。

补充记录重复读取、重复无效实验、错误根因尝试、回归引入率、人工纠正次数、每成功任务总成本。
对算法项目，还应记录复现误差、数据划分与训练/推理约束；不可只依靠 LLM judge。

## 4. 公平预算和因果边界

记忆后端比较固定基础模型、推理参数、Agent 提示、工具、输入证据、硬件与任务截止时间。
所有方法拿到相同的已知项目身份、分支和时间；项目过滤必须同样提供给支持它的基线。
现有按项目 FTS 不应被替换成跨所有项目的盲搜来制造优势。
两条比较轨道分开：统一 Agent 加不同记忆后端；各产品原生完整工作流。
第二条必须披露模型、hook、默认摘要、自动检索和工具边界的差异。

基线逐步加入：当前 Book、无历史记忆、预算内历史、人工维护的工程笔记、FTS、混合检索、实际开源系统。
调参工作量与开发数据一致；没有完成安装或没有成功运行的系统标记“未运行”。
当前已有适配器的旧版组件结果保留历史归属，不能自动升级成最新版完整产品结果。

冻结统一的最终上下文预算，并计入引用、分隔符、索引和后续页面读取。
此外记录原生响应负载、模型输入/输出 token、检索往返和后台模型调用。
摘要、嵌入和异步压缩的成本计入生命周期；在线任务延迟与摊销总成本分列。
离线准备越充分，可能在线越快；这种交换必须公开，不能只展示检索阶段。

冷进程、热进程、结果缓存命中、代码变更后的验证分别测量。
“冷进程”不等于清空了操作系统页缓存；只报告实际控制到的条件。
采用预先登记的配对顺序或平衡 AB/BA 顺序，并记录网络与模型服务排队影响。
运行次数、重试条件和超时策略事先固定；环境失败的恢复保留原失败记录与单独说明。

## 5. 真实代码项目回放接入协议

以下是待实施接口协议，不表示仓库已有这些适配器、数据集或自动化集成。

### 5.1 数据包与隔离

每个回放任务至少携带以下字段；任务输入与评测秘密分成两个文件，运行时权限隔离：

```json
{
  "task_id": "opaque-run-id",
  "project_family": "held-out-family",
  "project_id": "repository-id",
  "base_commit": "exact-source-commit",
  "environment_digest": "container-and-lockfile-digest",
  "cutoff": "event-log-prefix-boundary",
  "history_digest": "sha256-of-allowed-history",
  "request": "the-engineering-task",
  "budget": {"deadline_seconds": 1800, "memory_tokens": 2048}
}
```

上面的数字仅示意字段，不构成已登记的运行预算。
隐藏测试、预期补丁、评分器及题目类别保留在独立 evaluator；不得写入记忆库或 Agent 工作树。
适配器只收到完成任务必要的范围信息与问题；`project_family` 用于分组，不作为答案线索。
从公开真实项目取样也要过滤未来 commit、修复 PR、issue 后续答案与测试目录中的解题泄漏。

事件记录同时区分“系统何时获知”和“事实何时有效”。
阶段 t 仅摄取 `observed_at <= t` 的事件；晚到记录不能反向改变已经评分的过去查询。
原始来源、作者角色、会话、轮次、工具返回与可用代码快照均有稳定 ID 和内容摘要。
失败尝试是合法历史，但未来成功补丁及其总结不能出现在较早阶段。

### 5.2 每个任务的执行顺序

1. 从固定镜像和 `base_commit` 创建独立工作树，清理上个方法产生的模型状态、缓存与记忆。
2. 按事件顺序摄取允许的历史前缀，等待固定的后台完成条件，保存准备成本与归档摘要。
3. 同时向配对方法提供相同任务、当前范围、工具权限和预算，记录模型与记忆实现的精确身份。
4. 记录所有记忆查询、最终注入上下文、额外源文件读取、模型响应、工具输出和候选补丁。
5. evaluator 在独立环境验证候选补丁，保存退出码、测试结果与耗时；不向记忆系统泄漏隐藏断言。
6. 截止时保存成功或失败、最终工作树差异、完整成本和过程日志，不以替换问题修补失败样本。
7. 根据预先选择的轨道，决定后续任务是否看到本方法真实产生的历史，再推进到下一阶段。

必须分开报告两个轨道：**固定历史回放**控制摄取输入，便于比较记忆后端；
**闭环长期运行**允许前序成功与失败进入后续记忆，测量真实累积效果。
闭环中方法会产生不同历史，这是实验的一部分；不能只给某一方法注入标准成功轨迹。
若验证失败反馈允许 Agent 继续修复，各方法获得一致的反馈粒度，且从原始计时起累计成本。

### 5.3 可执行算法任务

| 任务族 | 可执行检查 | 必须保存的条件 |
|---|---|---|
| 排序、Top-K、近邻 | 空输入、重复值、稳定性、NaN、距离/相似度方向 | tie-breaking、索引语义、输入 dtype |
| 数值计算与归一化 | 溢出/下溢、大幅值、零范数、误差界 | 精度、epsilon、归一化轴、容差来源 |
| 数据处理与训练验证 | split 不交叉、预处理仅拟合训练集、seed 重放 | 数据摘要、split 版本、指标与聚合方式 |
| 批处理与推理优化 | 与参考实现一致、尾批处理、内存/延迟约束 | batch、设备、精度、输入规模和预热政策 |
| 依赖升级与兼容 | 旧/新配置转换、调用签名、回归套件 | 锁文件、API 版本、支持平台 |

测试应由任务规范或独立参考实现确定，不能从候选实现复制逻辑。
数值容差、性能测试预热、测量次数和硬件边界事先登记。
每个任务保存可重复的环境、执行命令和结果；受限环境未能执行的任务不得记为通过。

## 6. Holdout 与配对簇 bootstrap

先按项目族划分开发集与保留集，再在每个项目中按时间前缀回放。
同一模板的改名仓库、fork、共享任务生成器或高度相似数据属于同一族，不能跨边界充当独立泛化。
公开基准、历史已调参问题和新工程保留集分列；冻结项目、任务、环境与评测器摘要后才首次评分。
开发阶段可迭代；看过的保留集不能继续宣称未见，下一轮另留新族或后续时间窗口。

配对单位是相同任务、阶段与模型随机种子；统计重采样单位是项目族。
每次 bootstrap 对项目族有放回抽样，保留抽中族中所有方法的同一配对任务。
先算族内指标，再按预先确定的权重聚合，避免大项目凭任务数量支配总体结果。
建议登记 10,000 次重采样及 95% 区间，同时报告族数、任务数、实际样本权重和每族得失。
主指标、主要预算及主要比较对象提前指定；大量次要比较作为探索性结果，或预先登记多重比较校正。

族很少时，区间和显著性并不可靠；本轮四个合成算法类别尤其不能代表真实项目总体。
下一轮真实确认实验建议争取至少 20 个独立项目族，实际规模需先依据预算和先导效应量登记。
不要以重复同一确定性问题扩大“独立样本数”；重复主要用于耗时分布或模型随机性。

## 7. 建议推广门槛：全部为待登记目标，非实测

以下用于下一轮实验规划，不覆盖已有版本的固定验收规则，也不是本轮通过声明。

| 决策 | 建议门槛 |
|---|---|
| 合并定向正确性修复 | 新增失败复现转为通过；相关历史语义和隔离回归通过；披露测到的性能代价 |
| 声称提升真实工程成功率 | 主保留集成功率提高至少 5 个百分点，配对族区间下界大于 0；关键任务族不出现未解释退化 |
| 声称更快完成正确补丁 | 受限平均完成时间降低至少 15%；成功率差的区间下界不低于 −2 个百分点 |
| 声称有成本优势 | 同等成功率约束下，每成功任务总成本降低至少 15%，包含摄取、后台整理与失败尝试 |
| 推广跨项目迁移 | 有效迁移收益为正；错误迁移单独设上限，并报告区间，不能只报“零次观察到” |
| 启用自动 hook | 预先约定在线 P95 与 token 预算；越界可降级；默认开销和失败路径均有实测 |

多个门槛有冲突时记录明确取舍，展示质量—延迟—成本曲线，避免合成一个掩盖回退的总分。
不能根据一次受控实验声称“全面超越”；结论绑定具体版本、任务、环境、预算与比较边界。

## 8. 下一轮可执行 backlog

| 优先级 | 实现项 | 验收与消融 |
|---|---|---|
| P0 | 代码有效性：记录 repo/branch/commit、文件与符号、环境摘要；读取前检查证据变化 | 代码或依赖变化后标为待验证；比较无检查、时间衰减、变更验证的错误率与成本 |
| P0 | 真实回放 runner 与只供 evaluator 读取的隐藏测试 | 先跑无记忆、当前 Book、范围一致的 FTS；确认无未来证据和答案泄漏 |
| P1 | 条件迁移：经验分为可迁移结论与前提；项目身份与环境差异参与适用判断 | 同报错异根因负样本；同时测迁移成功和拒绝误迁移；消融条件匹配 |
| P1 | 失败实验记忆：保存命令、版本、输入、结果和失败条件；条件改变时允许重试 | 测减少重复无效实验，及错误阻止新可行方案的代价；消融失败记忆 |
| P1 | Agent hook 预算：任务恢复时小包检索，冲突或变更时升级验证，明确停止条件 | 测默认额外调用、上下文、P95和正确补丁时间；对照固定 top-k/固定预算 |
| P2 | 决策与证据可信度：区分建议、尝试、可见测试通过、独立验收通过 | 模型口头结论不能自动晋升；回归或反证可撤回，并保留原证据 |

文件没变不代表所有前提仍成立；commit 是祖先也不保证结论适用。
代码有效性检查应覆盖依赖、配置、数据与接口前提；无法确认时标注待验证，不伪造确定性。
“一直优化”落实为每轮保留基线、修复证据、保留集结果和回退记录，再决定下一轮是否推进。

| 项目 | 官方已公开的相关能力 | 比较时的边界 |
|---|---|---|
| [Mem0](https://github.com/mem0ai/mem0) | 用户/会话/Agent 作用域与元数据过滤，面向应用的记忆层 | README 的新版展示分数来自 managed platform，明确含 OSS SDK 没有的专有优化；OSS 与托管产品分别跑 |
| [Letta Code](https://github.com/letta-ai/letta-code) | 有状态 Agent、dreaming、技能学习、分层记忆与 Git 版本化 | 应比较当前实现；统一后端与原生 Agent 工作流分列，不能只对照旧 MemGPT |
| [Graphiti](https://github.com/getzep/graphiti) | 时间有效窗、事实失效、来源追溯、混合检索 | OSS 是自管图框架；Zep 是独立托管服务，性能与维护边界不同 |
| [claude-mem](https://github.com/thedotmack/claude-mem) | 编码工具活动采集、观察/摘要、项目过滤、索引到详情的渐进读取 | 现有 FTS 组件结果不能替代其完整观察和 Agent 检索流程 |

进一步核查来源：[Mem0 OSS 过滤](https://github.com/mem0ai/mem0/blob/main/docs/open-source/features/metadata-filtering.mdx)、
[Letta MemFS](https://docs.letta.com/concepts/memfs)、
[Graphiti 命名空间](https://help.getzep.com/graphiti/core-concepts/graph-namespacing)、
[claude-mem 搜索与 token 大小比说明](https://docs.claude-mem.ai/usage/search-tools)。
其中命名空间、时序、版本化、渐进读取均已有先例；本项目需要证明其工程适用性与结果收益。

[LongMemEval](https://github.com/xiaowu0162/LongMemEval) 可补充知识更新、跨会话和拒答测试。
[LongMemEval-V2](https://github.com/xiaowu0162/LongMemEval-V2) 已扩展到 web/enterprise 轨迹中的工作流、环境陷阱和前提差异，
并区分检索输入与评测秘密；其 QA 与查询延迟仍不能替代代码执行验收。
[LoCoMo](https://github.com/snap-research/LoCoMo) 及其 [ACL 论文](https://aclanthology.org/2024.acl-long.747/) 测长期对话能力，
适合作为补充；引用结果时必须锁定数据和评分版本，不能直接推断算法工程优势。
