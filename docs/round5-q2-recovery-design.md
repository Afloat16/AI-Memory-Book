# Q2 hosted reconstruction, before any execution

This independent attempt preserves the original Q2 helpers and evidence. It does not claim to restore the lost original SQLite bytes. A separate exact candidate source binding is mandatory before any claim or download. The scope JSON defines the full schedule and numerical/data boundaries.

## Sequence

1. Validate committed candidate binding, source/evaluator pins and all saved historical report/ledger identities without retrieval.
2. Claim the fixed result branch, prepare exact sparse source worktrees and verified model/data assets, then commit the frozen environment/asset binding.
3. Use the historical v0.3.1 builder once per cohort. Preserve each started intent and original preparation outcome. Require complete persisted-vector identity to equal the historical preparation before any query.
4. Bind new originals and database byte hashes separately; never replace historical originals or timestamps. Give all eight workers independent backups of the same new persisted vectors.
5. Execute the unchanged historical worker once per registered cohort/tokenizer/label. Compare each baseline to saved C2 payloads and each candidate to its new baseline. Publish intent and every complete/failed/partial outcome before advancing.
6. Audit the saved1,968 calls and984 full-payload pairs without invoking retrieval. Save all logs and failed evidence; no timing/quality gain claim follows from this compatibility check.

## Known risk requiring an explicit future decision

Exact historical vector bytes may differ on another CPU/runtime even when model files and packages match. The prepared identity check must stop before queries if that occurs. No automatic rerun, tolerance relaxation, timestamp rewrite or reattribution is permitted. Whether to investigate that blocker later is a separate decision; this scope does not approve a weaker gate.

The original scripts and reports are not changed. No model, dataset, embedding, retrieval or Q2 measurement has run while drafting this design.
