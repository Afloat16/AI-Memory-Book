# v0.8.0 — equivalent native text execution

This release moves five measured text-processing loops into a CPython C
extension while preserving the existing retrieval behavior. Python continues
to provide the public API, CLI, MCP, HTTP reader and integrations; SQLite keeps
the same schema, SQL and FTS5 index. The reference Python implementation remains
available.

## Changes

- Translate ASCII term handling, prepared ASCII/Unicode token loops,
  per-character excerpt folding with source coordinates, and evidence-unit
  boundaries into C. Preserve Python's Unicode code-point semantics, including
  expansion and combining-character cases. Dynamic helper overrides and
  unsupported argument types retain the Python path.
- Keep source/page IDs, pagination, project scope, ranking, character/token
  budgets, cache policy and schema 4 unchanged. Existing schema-4 archives need
  no migration. The runtime files remain the frozen measured candidate.
- Load the native backend by default when a compatible extension is installed.
  `MEMORY_BOOK_TEXT_BACKEND=python` selects the reference; `native` fails clearly
  if the extension cannot load; `auto` selects the available implementation.
- Deliver precompiled wheels for CPython 3.10–3.15 with the GIL on Linux
  x86-64/AArch64, macOS Intel/Apple Silicon and Windows x64. Resolve compatibility
  using the isolated installation environment's own Python tags. Verify the
  wheel and loaded extension hashes before switching the managed launcher.
- Retain a compiler-free Python wheel and source archive. Source builds support
  `MEMORY_BOOK_BUILD_NATIVE=1` for a required native build and `0` for the
  portable fallback. Free-threaded CPython currently uses the Python path.
- Compile the Docker extension in a separate build stage and verify native
  loading in the final image. Preserve failed preparation and existing
  environments when installation cannot complete.

## Measured results

The original frozen run compares the Python baseline with the C candidate using
four balanced A/B rounds, three passes per worker and the same queries, budgets,
cache policy and SQL. All **113,568 timed calls / 56,784 pairs** pass the recorded
full-output, source-coordinate, scope, budget, archive and index checks.

| Dataset | Surface | Python p95 | C p95 | Latency reduction |
|---|---|---:|---:|---:|
| synthetic61 | Direct recall, 2400 chars | 7.455 ms | 6.751 ms | **9.44%** |
| synthetic61 | Real SDK stdio MCP, 2400 chars | 8.682 ms | 7.974 ms | **8.15%** |
| public1015 | Direct recall, 2400 chars | 2.886 ms | 2.826 ms | **2.07%** |
| public1015 | Real SDK stdio MCP, 2400 chars | 4.009 ms | 3.934 ms | **1.85%** |

Each default-budget cell improves in all four paired rounds. At the separately
tested 1024-token cap, p95 reductions are 15.60%/13.53% for synthetic direct/MCP
and 3.82%/2.85% for public direct/MCP. All eight configurations and their
round-level results remain in the
[complete validation record](../native-language-validation.md).

Fresh-ingestion medians fall by 15.28%/15.96% and unchanged-reingestion medians
by 21.98%/31.69% for synthetic/public data. These resource measurements use only
four workers per implementation/cohort. Module import adds about 0.57–0.77 ms,
MCP initialization has no consistent improvement, and memory is approximately
unchanged or slightly higher. Database sizes are exactly equal.

These are regression/performance results on one hosted Ubuntu/CPython 3.12
machine. They exclude model generation, have no query-result cache hits, and
retain normal SQLite/OS caches. They do not establish new answer quality,
cross-platform speedups, whole-product latency or a universally optimal language.
The older v0.6.0 component comparison retains its original evidence boundary.

## Installation and upgrade

Use the pinned installer in the [deployment guide](../deployment.md). Its output
reports `Default text backend: native` or `python`; `installation.json` also
records the installed extension hash. Check the environment's own interpreter:

```bash
python -I -c "from memory_book._text_backend import BACKEND_NAME; print(BACKEND_NAME)"
```

After upgrading, refresh the configured clients and any existing background
service to use the new launcher, then restart those clients. Preserve the same
database and configuration paths. Schema-4 archives require no migration;
archives on earlier schemas should follow the existing backup/migration guide.
The default remains 2400 characters, five results and optional exact token caps.
The MIT license is unchanged.
