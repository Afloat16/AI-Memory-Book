# v0.11.0 — addressable project memory and qualified revisions

This release adds the directory-search step needed to navigate engineering
memory as books, chapters, sections and original evidence pages. It also
recovers brief later declarations that repeated older records could keep
outside the current-state comparison pool. Explicit project scope remains the
boundary between similar engineering projects.

## Runtime changes

- Add `MemoryBook.search_directory`, CLI `locate`, MCP `search_directory` and
  HTTP `/api/locate`. Search existing indexed title, question and directory
  metadata, group chapter hits before pagination, and return up to five section
  previews for each matching chapter. Metadata uses analyzed-term OR matching;
  it is a locator, not an exact-phrase or semantic answer guarantee.
- Validate project/chapter constraints before searching. Unknown or conflicting
  constraints fail without widening the search; a bound MCP connection supplies
  its exact project. Results identify themselves as `result_type="directory"`
  and `evidence=false`. Follow the returned IDs to original pages before citing
  facts; titles and extractive summaries are navigation hints.
- Read each directory request's metadata and counts in one SQLite snapshot,
  including `toc` and section reads. `toc` and the locator also read their
  reported revision in that snapshot; section responses have no revision field.
  Preserve caller-owned transactions.
  Separate requests can observe different revisions while capture continues.
- For current-state recall, supplement chapters already reached by relevance
  search with recent lexical candidates. Apply project/task/session constraints
  before the supplemental SQL limit. No more than 96 additional matching rows
  are retained across those chapters; this does not bound all database scan,
  sort or source-check work.
- Authenticate each proposed page against its complete original turn before
  comparing field declarations. Qualify every addition to the original pool,
  including candidates already present in the FTS tail, before score changes
  or duplicate-body selection. Recheck field grouping after rejected additions
  are removed.
- When a query has additional qualifiers, require each compared field to have
  one simple declaration with those terms as its adjacent qualifier. Apply the
  same rule to the added proposal and its original-pool anchor. Other sentences,
  user questions, other fields and ambiguous repeated declarations cannot lend
  a qualifier. Complex but valid prose may remain outside this supplemental
  route.
- Reuse only pure declaration and quotation parsing for byte-identical bodies
  within a call, after every page has independently passed source authentication.
  Custom source readers retain the conservative path.

## Evidence and scope

The complete source acceptance, original failed attempts, fixed engineering
replays and directory contracts are retained in the
[v0.11 validation record](../v0.11.0-validation.md). They are authored
development/regression evidence. They do not measure coding-model accuracy,
production task completion or unseen-workload generalization.

The accepted runtime is bound to source checkpoint `6619724`; later release
documentation/tooling commits retain its exact runtime bytes. The baseline and
selected source each completed 800 independently scored engineering responses
with zero per-case score changes or regressions. The unchanged directory-v2
protocol passed 119/119 contracts. On each of the Python and native backends,
six crowding configurations repeated three times recovered the brief correction
3/18 times on the baseline and 18/18 on the selected source; each backend's
18 relevance controls remained identical after excluding only latency. The two
unchanged review reproductions also preserved the earlier correct decision in
all four authored candidate configurations.

The complete immutable-source local suite ran 1,603 tests: 1,589 passed and 14
were skipped, with zero failures/errors. Two require Windows and twelve require
optional PyArrow. These local observations do not replace the exact-commit CI
or installed native-wheel tests.

The new external execution uses actual Haystack 3.5.0, BM25S 0.3.16 and
Memvid SDK 2.0.160 APIs on the unchanged engineering fixture. Together with
six retained external configurations, nine external configurations have been
executed; eight have scored rows in the common comparison. Architecture
documentation covers 21 external project families, including four library or
framework building blocks. This is not 21 complete products benchmarked.

BM25S matches Book's complete-evidence and fixed-policy counts at 2,400
characters, and exceeds Book's common-block counts at 1,200 characters.
Haystack returns complete evidence for 66/72 answerable cases at both budgets.
Memvid's original natural-language queries returned empty native hit lists in
the tested lexical configuration; the separately retained keyword diagnostics
do not replace those queries or establish a product-level zero score.
[Full settings, denominators, results and reproducibility](../current-results.md).

Current-state qualification is intentionally limited. The original comparison
pool retains its existing fallback ordering and can still prefer a recent
agenda or mixed-context statement. Chronology and field syntax do not establish
decision authority, resolve every conflict or guarantee completeness. Relevant
revisions can also remain outside already-reached chapters or the finite
supplemental candidate set. No universal superiority or new speed claim is made.
The README retains earlier performance experiments with their original runtime
identities and recorded regressions.

## Compatibility and upgrade

Schema 4, existing source/page IDs, Unicode code-point coordinates and the
22-entry native implementation remain. Existing schema-4 archives need no new
schema migration. The recall-cache version increases to 19; an expected cache
miss after upgrading does not remove source records. The default remains
lexical retrieval with 2,400 characters and five results. Semantic retrieval
and exact token caps remain optional.

Use the pinned v0.11.0 installer in the [deployment guide](../deployment.md).
Retain existing database/configuration paths, per-client project bindings and
write preferences. Restart configured clients and background capture processes
to load the new runtime. Archives on older schemas follow the existing verified
backup and schema-4 migration procedure.

Publication requires the exact release commit's complete 11-job CI, all 30
native wheel cells from one release run and attempt, verified fallback packages,
and a real installation through the public release URL. Preparation notes do
not substitute for those delivery gates; completed publication evidence is
recorded separately from source acceptance.
