# v0.3.4 — Faster startup and atomic initialization

Release scope: **faster CLI startup and atomic initial schema/FTS creation, with preserved retrieval outputs**. Startup acceptance includes an explicitly reviewed resource tradeoff; the complete fresh comparison passes its integrity and output-equivalence checks. Publication is gated on the exact release commit's nine-job CI and verified package/public-installer workflow.

The confirmed improvements are new-archive construction and actual CLI help/version startup. This release uses exact source A, with its rejected dense-project ranking experiment excluded. Existing archives retain schema 3, source addresses, citations, token budgets and the public `MemoryBook` class.

## What changes

- Initial schema and FTS creation share one immediate transaction. The empty/schema checks are repeated after acquiring the lock, complete trigger statements stay intact, and a schema setup failure rolls back. The subsequent covering-index and connection PRAGMA steps keep their prior boundaries.
- Package and command metadata load without eagerly importing the archive, transcript importers and client/capture machinery. Explicit `MemoryBook` import still loads the complete API; class identity, star import, type hints and CLI class overrides remain covered by tests.
- Native FTS candidates retain narrow metadata only within the same recall, removing a redundant metadata read while preserving complete directory validation. Custom factories/connections and constrained or uninspectable SQLite limits retain the previous query path. Python 3.10 takes that conservative metadata fallback.

## Measured startup gains and retained costs

The unique [prospective confirmation](https://github.com/Afloat16/AI-Memory-Book/actions/runs/43598913606) completed all **480 original samples and 960 events**, with four AB/BA/BA/AB rounds on Ubuntu 24.04 / Python 3.12, fixed MCP 1.30.0 and Pydantic 2.14.3. Each source contributes forty fresh samples per boundary. No first sample, outlier or failed result was removed, and no timing was repeated.

No syscall/component trace identifies the exact cause; the increase is not dismissed as noise or attributed to the new-schema transaction.

## Retrieval evidence and scope

A's balanced development experiment completed **22,988 calls / 11,494 complete output pairs / 45,976 events** with all complete non-timing outputs equal. Recall improvements were roughly **1%**, insufficient to advance to the original **10% aggregate / 15% public native / 10% actual MCP p95** targets. That four-round formal recall matrix was **not run or accepted**. B regressed public native p95 approximately **19–29%** and actual MCP p95 **23.9246%**; it remains excluded with its entire experiment preserved.

The exact A runtime also matches all **2,304 historical Hotpot256 complete outputs** against v0.3.3, independently audited against **4,608 events**. These are compatibility results, not new retrieval-quality gains. Historical C7 and optional Q2 results retain their original versions and measured boundaries.

Book exceeds claude-mem's annotation recall and completeness in all six tokenizer/cap cells and has the highest packed-context MRR among the four component implementations in all six. Ai-memory has higher recall and completeness in all six; billion has higher recall in all six and higher completeness at 1,024/2,048 tokens. Book's small 512-token completeness advantage over billion and all per-question losses remain visible. The seven-question low-overlap group also remains: Book completes 0/7, claude-mem 1/7, and ai-memory/billion 2/7 at 512 cl100k tokens. This is **no new retrieval-quality gain against v0.3.3 and no universal competitor lead**.

Fresh timings are descriptive and use a fixed sequential stage order. Five of six native p95 cells increase by **0.23–2.92%**, while o200k/512 decreases **3.39%**; all six native means increase **0.136–3.494%**. Component search p95 increases **3.517899 → 3.582246 ms**, about **1.83%**. Native sampled setup/query RSS increases **547.41 → 551.45 MiB / 533.12 → 537.18 MiB**; component setup wall increases **840.940 → 843.362 ms**. The larger Book native response payload, all repetitions, setup phases, RSS, storage and packing costs remain in the full results. These observations are not dismissed as noise and do not establish a causal recall change from this stage order.
