# v0.10.0 — bounded reads and reliable delivery

This release reduces repeated work around semantic retrieval and chapter
directories and fixes reproduced import, capture and installation problems.
It retains the 22-entry native backend introduced in v0.9.0.

## Runtime changes

- Read semantic vectors in the same 4,096-row numerical batches without first
  materializing every vector blob in Python. Retain SQL ordering, all vector
  validation, floating-point operations, ties and final ranking.
- Read and hash each pinned model artifact once into a verified snapshot.
  Optional runtimes consume those exact bytes, preserving model identity,
  replacement protection and telemetry opt-out before runtime imports.
- Share chapter metadata and group page counts while retaining the original
  indexed, bounded preview query for each section. Standard directory reads share one coherent snapshot; custom
  section overrides and caller-owned transactions retain their behavior.
- Preserve valid Unicode separators inside JSONL message strings and enforce
  the existing import limit on actual bytes read, including growing files.
- Query Windows worker status through a read-only process handle. Correct
  capture's path-versus-descriptor metadata comparison so completed Windows
  file updates are imported while concurrent modifications are deferred.

## Installation and release changes

Managed launchers, interpreter probes and bootstrap helpers use isolated
Python with explicit UTF-8. New MCP and service commands generated from those
launchers retain isolation; services also request unbuffered output explicitly.
Existing nonisolated source workflows retain their command prefixes.
The installer retains its ownership checks, staged activation and rollback.

Native artifacts are separated by workflow run and attempt, and aggregation
requires the matching attempt. Native test receipts require one complete
144-test outcome and only specifically allowed optional skips. Unexpected
skips, expected failures and inconsistent summaries fail the release cell.
The release runbook now describes all 11 CI jobs, 30 native cells and 67 assets.

## Compatibility and evidence

Schema 4, public retrieval fields, source/page IDs, Unicode code-point
coordinates, project scope, lexical ranking, segmentation, budgets and recall
cache behavior are unchanged. Existing schema-4 archives need no migration.
The default remains lexical recall with 2,400 characters and five results;
semantic retrieval and exact token caps remain optional.

The frozen semantic component comparison measured 6.38% lower paired latency
and 66.31% lower tracked peak allocations at 32,768 vector windows. The
4,096-window case was 1.41% slower, about 0.329 ms between pooled medians.
Artifact reads and hashes each fell by half; mocked-runtime initialization
was 41.50% faster. These measurements exclude real model loading, inference,
full recall and MCP, and tracked allocations do not represent total RSS.

The accepted directory implementation reduced paired latency by 5.31% and
6.46% for 20 and 100 sections with 20 preview pages each. All six multi-section
configurations improved in all four pairs. Two single-section configurations
were 1.07% and 0.42% slower, about 2 and 4 microseconds between pooled medians.
All 1,440 timed calls retained exact outputs and bounded preview reads. The
earlier compound-query implementation was rejected after seven of nine
configurations became slower; its complete results remain available.

See the [complete v0.10.0 validation report](../comprehensive-v010-validation.md)
for the component measurements, raw records, retained regressions and final
delivery evidence. This round does not rerun or relabel the earlier native
recall/MCP performance experiment and makes no new retrieval-quality claim.

## Upgrade

Use the pinned v0.10.0 installer in the [deployment guide](../deployment.md).
Compatible platforms receive a verified native wheel; other environments
retain the Python fallback. Keep existing database and configuration paths.

Run the new launcher's `setup` for each existing client, retaining its project
binding and write preference, and reinstall any configured background service.
Restart those processes so they use the new environment and command flags.
Older schemas follow the existing backup and schema-4 migration procedure.
Previous installation environments and memory data are retained.
