# v0.13.0 — complete evidence across similar project histories

This version improves the selection of original current-policy and boundary
evidence in long engineering histories. It preserves exact project/source
coordinates, handles a bounded set of bilingual declaration forms, and reduces
repeated directory work. The measured tradeoff is explicit: evidence coverage
improves, directory navigation is faster in every measured group, and many cold
recall groups are slower.

## What changed

- Qualify repeated declarations only when every literal mention independently
  establishes the same field, scope and value. Quoted, conditional, negated or
  unrelated text cannot silently establish a current decision.
- Recognize bounded Chinese declaration and English reporting forms while
  preserving actual field names, namespace boundaries, occurrence queries,
  environment qualifiers and revocation controls.
- Keep current declarations above authenticated no-change reports only when
  doing so preserves the requested facts. A query about a checklist result or
  review action retains that report's own source, including later changes.
- Return bounded evidence assessment and conflict pointers, including compact
  MCP guidance. These describe the reached candidate pool; they do not certify
  whole-archive completeness, factual authority or safe abstention.
- Batch directory search and current-revision candidate work, bound useful
  project row ranges, and use a guarded single-cursor membership filter for
  small interleaved projects. Original global FTS ranking remains in use;
  chapter/session paths retain their established planner behavior.
- Prepare query/declaration terms after a validated result-cache miss. Project
  assertions, revision checks and other correctness checks remain in force.

## Performance benefits and retained costs

All comparisons below are from the same second run. Six balanced AB/BA rounds
provide 30 cold and 90 warm recall observations per query/arm/checkpoint and
30 complete directory observations. Cold clears the recall-result cache,
not the OS or SQLite page cache. Directory timing includes discovery, section
navigation and original-source reading. Initialization, restore, scoring and
result journaling are outside the query timer.

| Pooled p50 direction | Faster groups | Slower groups |
| --- | ---: | ---: |
| Cold-result-cache recall | 12/49 | 37/49 |
| Warm-result-cache recall | 42/49 | 7/49 |
| Complete directory navigation/read | 14/14 | 0/14 |

| Representative query | Baseline p50 | Candidate p50 |
| --- | ---: | ---: |
| 100k interleaved, archived current recall | 166.898 ms | 102.478 ms |
| 100k interleaved, archived historical recall | 133.222 ms | 67.912 ms |
| 100k interleaved, archived full directory/read | 159.154 ms | 26.707 ms |
| 100k grouped, archived full directory/read | 157.307 ms | 9.958 ms |
| 1,024 pages, archived current cold recall | 6.726 ms | 10.516 ms |
| 1,024 pages, multi-source cold recall | 7.235 ms | 11.316 ms |
| 100k interleaved, active current cold recall | 332.062 ms | 338.309 ms |

The slow multi-source baseline is incomplete while the candidate is complete;
both timings remain visible. All seven slower warm groups are this multi-source
query, with approximately 6.36–9.33% higher pooled p50. The archived-current
small-corpus slowdown also remains despite both versions returning complete
evidence. The full [112-group review](https://github.com/Afloat16/AI-Memory-Book/blob/v0.13.0/benchmarks/reports/v0.13-development/scale-run2-review/scale-run2-summary.md)
includes p95, all six paired ratios, resource costs and every adverse group.
The paired-round and pooled statistics are different estimators.

**Fixed-size old projects still incur growing cost as unrelated history grows.**
For the unchanged archived target, candidate directory p50 increases from
0.7692 to 1.5787 to 4.9298 ms across 1,024, 10,016 and 50,016 total pages.
Global FTS work remains. This release does not achieve constant-time access,
universal speedup, lower memory in every case or a production latency guarantee.
Timestamp age alone preserves all 72 evidence projections per arm; this is
separate from growth and physical-layout effects.

## Compatibility and delivery

Schema 4, existing source/page IDs, project-bound MCP navigation and the
22-entry native backend remain. The six native C/header files are unchanged.
An existing schema-4 archive requires no new migration. Recall-cache version
26 causes expected cache misses after upgrading without deleting source records.
Defaults remain local lexical retrieval, 2,400 characters and five results;
semantic retrieval and exact-token limits remain optional.

Use the [deployment guide](https://github.com/Afloat16/AI-Memory-Book/blob/v0.13.0/docs/deployment.md)
and preserve database paths, project bindings and capture preferences. Restart
clients and workers to load the new runtime. Earlier schemas use the existing
verified-backup and schema-4 migration procedure.

Publication is gated by the exact release source's eleven CI jobs, all thirty
native build/install cells, package checks and the real public-URL installer.
The workflow appends the actual source, CI and release-run links to this body.
The maintained [current validation record](https://github.com/Afloat16/AI-Memory-Book/blob/main/docs/v0.13.0-validation.md)
records the subsequent independently audited delivery status. Source evidence
alone does not substitute for those delivery gates.
