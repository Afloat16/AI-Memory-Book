# v0.6.0 — current configuration evidence and broader open-source comparisons

This release improves how an engineering archive distinguishes configuration
revisions from later maintenance discussion. It also adds a reproducible
comparison with six external open-source implementations and a documented
architecture review covering fourteen external project families. Results apply
to the measured configurations and synthetic engineering workload, with full
source evidence and the unmeasured parts of each product identified separately.

## Keep current configuration evidence usable

For current queries, a later mention of a field should not automatically inherit
the ranking position of a statement that assigns its value. The bounded
candidate pool now separates explicit declarations from maintenance mentions.
Within the same task and remaining query constraints, declarations of the same
field are ordered by source time while retaining the existing relevance slots.
Field values do not enter the grouping key or score.

Naming variants such as `retryLimit=3` and `retry_limit=5` remain comparable.
Limited, clear prose such as `retry limit is now 7` can participate too.
Word boundaries and qualified names remain distinct: `a_bc` differs from
`ab_c`, and `worker.limit` differs from `worker_limit`. A comparison such as
`retry_limit == 7` may identify a field name but does not declare a new value.

Only a page whose contents equal its complete original turn can supply a
declaration hint. The implementation checks that equality inside the existing
SQLite read snapshot. Recognized quoted logs, inline or fenced code, examples,
questions and conditional language are excluded; quote boundaries survive
sentence and line breaks. A first continuation page cannot pass merely because
its source coordinates start at zero.

The analysis is limited to 64 query-relevant fields and 64,000 characters per
candidate. Oversized or ambiguous input retains the existing candidate path.
Unclassified evidence is not deleted. This is a conservative syntax heuristic,
not verification of truth, team approval, arbitrary negation or rollback intent.
The bounded pool and a small context budget can still omit necessary evidence.

## API and archive compatibility

Python, CLI, MCP and HTTP keep `temporal=auto|current|relevance` and the existing
default of 2,400 characters with up to five results. Detailed responses expose
`temporal.declaration_ordering`, including classification counts and fallback
reasons. MCP compact output keeps its existing shape; use `details=true` when
the diagnostic is needed.

Historical/relevance queries and recognized event-count or timeline queries
retain their previous paths. Optional semantic candidate fusion reuses the same
current-declaration rule. No embedding model or extraction LLM is added to the
default retrieval path.

The release keeps schema 4, source text, page addresses and source coordinates.
Recall cache version 16 prevents reuse of entries produced by the earlier
ordering rules. A schema-4 archive needs no new migration. For an older schema,
follow the existing [snapshot and upgrade procedure](../deployment.md#schema-4-upgrade).
Update and restart the clients and capture services that share the archive.

## Reproducible comparisons

The new matrix supplies the same original pages, unchanged questions, project
filter and top-five limit to Book and six pinned external implementations:
billion-context, claude-mem, Basic Memory, Mem0, Chroma and LangGraph Store.
The unchanged common whole-block packer applies both 1,200- and 2,400-character
budgets. Native Book excerpt results remain a separate track.

The protocol fixes every mode before quality scores are inspected. Mem0 uses
`infer=False`; Basic Memory uses explicit native FTS; claude-mem receives raw
observations without its observer. Chroma and LangGraph are retrieval/store
infrastructure. Chroma, LangGraph and Mem0 share a real local MiniLM model, so
their results are correlated evidence of that configuration. Default full-product
workflows, managed services and unmeasured projects do not inherit these scores.

Dependencies and distributions are hash locked. Original package files and
the official model archive are verified, provider credentials are not inherited,
and measured Python workers reject network connections. Failed native calls
remain failures rather than becoming successful zero-match responses.
The evidence includes source mappings, complete native output, per-checkpoint
settings, both budgets and all missing-evidence questions.

See the [validation record](../v0.6.0-engineering-validation.md),
[registered protocol](../../benchmarks/competitors/memory-systems-plan.md),
[retained reports](../../benchmarks/reports/v0.6.0-engineering/) and
[fourteen-family comparison](../open-source-memory-comparison.md).
The cases were used during development; no coding LLM or independent holdout
was evaluated. Fixed-policy checks do not measure generated-code accuracy,
developer productivity or total inference cost.

## Observed engineering results

At the default **2400-character** budget, both native and common-block Book
recover **72/72 complete-evidence cases** and pass **48/48 fixed-policy cases**,
with zero stale-only cases. In the common-block comparison, the three tested
lexical components each have 64/72 complete cases and 40/48 policy passes; the
three shared-MiniLM configurations each have 47/72 and 25/48. These are six
executed components with the modes and boundaries described above.

At **1200 characters with common whole-block packing**, the retained-source
comparison improves from **52/72 to 68/72 complete cases**, **28/48 to 44/48 policy
passes**, and **12 to 4 stale-only cases**. There are sixteen complete/policy
gains and no losses against that source. The four remaining training-decision
failures are still disclosed: each tested lexical competitor wins those four
cases while losing eight others to Book. Native excerpt quality is unchanged
at both budgets; its 1200 policy result must not replace the common-block score.

The independent result audit passes **116,693 checks**, including **320/320
complete response pairs** between the old and expanded component harnesses.
All seven backends return related context for every missing-evidence question,
so the results do not establish reliable abstention. Full results, paired cases,
raw output and the failed pre-quality integration attempt remain in the
[validation record](../v0.6.0-engineering-validation.md).

## Installation and release checks

The Python, Bash and PowerShell installers target the v0.6.0 release wheel.
Historical wheel routes remain available. The default isolated environment
includes MCP/client support; none of the heavy comparison dependencies or
benchmark model weights are added to the normal package.
Use the [installation guide](../deployment.md#install-v060).

The frozen runtime passed the local suite of **1,097 tests: 1,096 passed and one
Windows-junction test skipped on Linux**, with zero failures or errors and no
runtime changes during testing. Eleven new declaration-regression methods and
ten initial comparison-contract tests are included. Two later serialization tests and
eleven independent-audit tests also pass as a separate 23-test adapter/audit group. Final-source cross-platform CI,
packaging and public-installer checks are separate publication gates.
