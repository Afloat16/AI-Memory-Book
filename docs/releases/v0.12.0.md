# v0.12.0 — source-local revisions and complete short records

This release improves evidence selection when similar engineering histories
contain different environments, later nondecisions or brief corrections. It
also completes short source records within the existing context budget while
protecting current-state evidence already allocated space.

## Runtime changes

- Require authenticated, statement-local comparable declarations for temporal
  relevance transfers throughout the current-state comparison pool. A later
  timestamp alone cannot transfer another page's relevance to an unclassified
  agenda or a declaration for a different explicitly stated scope.
- Retain explicit field qualifiers and bounded numeric prose. Authenticate full
  original turns behind partial comparison anchors; another sentence, directory
  title or unrelated field cannot supply the missing qualifier.
- Restrict Chinese old-value explanations to complete withdrawal statements
  with guarded reasons. Keep pending approval, staging-only suffixes and other
  ambiguous continuations from gaining current-state promotion through that
  grammar. Complex valid prose can remain outside the recognized patterns.
- Protect the authenticated current turn when constructing an excerpt from a
  page with several turns. Chronology and title metadata alone cannot establish
  that a later turn answers the scoped question.
- Complete source pages of at most 240 characters using available allocation
  from longer truncated pages, while preserving their existing 120-character
  minimum. Preserve candidate order, citation headings, already complete pages
  and current turns that fit their assigned space.
- Start exact-token first-fit assembly with the same protected character
  blocks. Preserve every whole block it can accept before using the existing
  token-unit supplementation. Character and exact-token limits both remain in
  force.

## Broader configured-component comparisons

The newly executed components are LanceDB 0.41.0 lexical full-text search and
Whoosh 2.7.4 with OR queries and BM25F. Their protocols were committed before
quality execution; 480 native calls and 320 packed responses use the unchanged
80-question engineering fixture and identical supplied-page bundles.

The comparison now contains eleven executed external configurations: ten
scored configurations and Memvid's separately diagnosed original-query
limitation. The architecture review covers 26 external project families; this
is not 26 complete products benchmarked.

**Book, BM25S and the configured Whoosh mode tie at both character budgets** on
complete-evidence and fixed-policy counts. Whoosh uses fewer mean packed
characters. LanceDB's tested FTS configuration returns complete evidence for
64/72 answerable cases at both budgets, with four stale-only cases. Historical
external executions retain their original source identities; a fresh Book
replay does not rerun those products. The [current results](../current-results.md)
identify versions, configuration boundaries and the common packer.

## Retained limits

High original lexical relevance can still rank an agenda ahead of a decision.
The change controls temporal transfers; syntax and chronology do not determine
general decision authority or resolve equal-time conflicting declarations.
Missing-evidence queries still return related context, so calibrated abstention
is not established. Zero stale-only cases under the fixed metric does not mean
old and current text can never coexist in a response.

The finite supplemental candidate pool can miss evidence outside already
reached chapters; its cap does not bound all database or source-check work.
Project assertions guard accidental scope changes and do not provide multi-user
authentication. Existing historical speed measurements retain their original
runtime identities: no new latency comparison or whole-runtime speedup is
claimed for v0.12.

## Compatibility and delivery

Schema 4, source/page IDs, Unicode code-point coordinates, project-bound MCP
navigation and the 22-entry native backend remain. All six native C/header
files are unchanged from v0.11; the Python retrieval orchestration changes.
Existing schema-4 archives need no new migration. The recall-cache version is
21; an expected cache miss after upgrading does not remove original records.
The default remains local lexical retrieval with 2,400 characters and five
results. Semantic retrieval and exact-token caps remain optional.

Use the pinned v0.12.0 instructions in the [deployment guide](../deployment.md)
after publication. Preserve database/configuration paths, client project
bindings and write preferences. Restart configured clients and background
capture processes to load the new runtime. Older schemas follow the existing
verified-backup and schema-4 migration procedure.

Source acceptance is complete. Publication requires the exact preparation
commit's 11 successful CI jobs, 30 native wheel cells from one release run and
attempt, verified fallback packages, and successful installation through the
real public release URL. Completed delivery evidence is recorded separately;
these preparation notes do not claim that those new publication gates have
already run.
