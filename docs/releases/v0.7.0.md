# v0.7.0 — book navigation for similar engineering projects

AI-Memory-Book treats an engineering archive as a shelf of project books.
Select the exact project, find a question through its directory, open the
relevant chapter/section/page, then read the complete original conversation
turn. This release makes that route explicit across Python, CLI, MCP, HTTP and
the local reader, with checks that keep similarly named projects separate.

## Select a book before recalling evidence

An archive with multiple projects now rejects a recall request that has neither
an exact project nor an exact chapter. A session name, repository display name
or words in the question do not guess the intended project. A sole project can
still be resolved automatically. A deliberately cross-project request must use
`all_projects=True`, CLI `--all-projects`, or the corresponding MCP/HTTP boolean.
It cannot be combined with an explicit project. Blank scope values are invalid.

This is a deliberate API behavior change: applications that intentionally
search every project must declare that intent. Normal exact-project retrieval
keeps its existing ranking, budget and source evidence behavior. Scope resolves
inside the read snapshot and before cache lookup. An explicit project and a
foreign chapter remain an empty intersection rather than broadening the query.

Project IDs are exact identities, including case and punctuation. Different
books may share a display name and session IDs. The reader displays the stable
IDs and carries the selected project into subsequent address reads. Filesystem
capture continues to derive identities from its configured project/root rules;
users should inspect those mappings when copying or moving repositories.
Project scoping prevents accidental mixing; it is not authentication or an ACL.

## Find the question, then recover the complete source

- `search_directory(query, project, offset=0, limit=20)` searches the existing
  title, question and directory fields. It groups matching continuation pages
  by section before pagination and returns metadata, breadcrumbs and original
  source addresses. It does not search the answer body. Use `recall` when the
  distinguishing term is only in the answer.
- CLI `index` and MCP `search_directory` expose that operation. HTTP serves it
  at `/api/directory`; the reader has a separate directory-search mode.
- `chapter`, `section` and `read` accept an optional exact `project` guard.
  A valid address in another book is rejected. Use this guard on every follow-up
  read to preserve the selected book, including in client integrations.
- `read_turn(project, session_id, turn_index, ...)`, CLI `turn`, MCP
  `read_source_turn` and HTTP `/api/turn` read the complete normalized original
  turn independently of page splitting. Character pagination preserves message
  indices and original-turn coordinates. The reader can load subsequent chunks.
- Page and original-turn reads expose the source session's SHA-256. Carry
  `source_hash` into each turn continuation; replacing that session causes a
  clear refusal instead of silently concatenating different source versions.

Directory and nested chapter/section responses use one SQLite read snapshot.
They preserve a caller-owned transaction. Each separate directory pagination
request has its own snapshot; restart if the returned archive revision changes.
Original-turn chunks are bounded in SQL, including question metadata. The
content limit does not cap the complete JSON envelope or model token count.

## Compatibility and installation

The archive remains schema 4; no new source migration is required. Source text,
existing page addresses and source coordinates remain preserved. Recall cache
version 17 keeps earlier implicit-scope responses out of the new cache path.
The default stays **2,400 characters, up to five results, lexical retrieval**,
without a default embedding service or memory-extraction model call.

Python, Bash and PowerShell installers target the v0.7.0 wheel and retain their
historical release routes. Default MCP/client extras remain separate from heavy
comparison environments. Update and restart clients/capture services sharing
the archive. See [installation](../deployment.md#install-v070).

## Validation and comparison scope

The registered comparison has Book and seven external component configurations:
billion-context, claude-mem, Basic Memory, Mem0, Chroma, indexed LangGraph Store
and ReMe's native file/BM25 path. Source, package/model artifacts, query text,
packing and scoring are fixed before quality inspection. The expanded feature
review covers eighteen external project families; unmeasured full products
receive no inferred numerical score.

Two separate 80-case cohorts cover the established engineering regression and
eight deliberately similar project identities. The latter reuses project
display names, task titles, session names and parameter names with conflicting
policies. It includes source replacement and both globally absent facts and
facts present only in another project. Navigation/scope API contracts are a
separate Book-specific track, not zero scores assigned to untested competitors.

The unchanged common whole-block packer runs at 1,200 and 2,400 characters;
native excerpt results remain separate. Every native output and failure is
retained. Three repetitions measure stability/timing, not three independent
quality samples. These are authored development cases, without an independent
holdout or generated-code productivity study. No namespace is treated as a
multi-user security boundary.
