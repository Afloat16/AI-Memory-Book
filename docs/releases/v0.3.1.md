# v0.3.1 — Faster project-scoped recall, identical evidence

AI-Memory-Book gives agents a shared local archive of original evidence. This
experimental patch reduces SQLite query work for eligible project-scoped
recalls, preserves the complete non-timing response, disables optional runtime
telemetry before model initialization, and improves interrupted release recovery.
The lightweight default remains Python + SQLite with zero model calls for
memory writing and lexical retrieval.

## Highlights

- **Faster default retrieval:** across ten registered configurations and four
  balanced rounds, the geometric mean of pooled p95 ratios improves **11.36%**.
  On the 1,015-question public-conversation corpus, native 4,000-character
  recall p95 falls **26.05%**, and actual MCP stdio p95 falls **19.87%**.
- **Identical evidence and interfaces:** the 47,320-call performance experiment
  passes complete non-timing payload equality and source/scope/budget checks.
  The optimization preserves global BM25 statistics, ranking, result limits,
  cache identity, source addresses and existing context-budget behavior.
- **Local semantic initialization:** Book sets `ORT_DISABLE_TELEMETRY=1`
  before importing ONNX Runtime and calls its telemetry-disable API before
  creating an inference session. Model files, vectors and Q2 fusion rules keep
  their existing identities.
- **Recoverable publication:** release tooling uses the creation response's
  draft identity, polls read-only visibility checks, verifies uploaded assets,
  and reconciles an already published exact release without repeating writes.
  Installers select the v0.3.1 universal wheel and retain the v0.3.0 wheel route.

## Measured default-retrieval improvement

The frozen experiment compares v0.3.0 commit
`dd2f88be742ed330269e7dd5915b6f75089d7fef` with candidate
`2d199b93f650eccd3dd239178822b31001b880e3`. It retains **47,320 timed calls**,
**16 workers**, two old regression corpora, five configurations per corpus and
four balanced baseline/candidate rounds on the same host. Result-cache reuse
is excluded; actual MCP calls retain the normal cache-write cost. OS and
SQLite caches are warm.

| Public-conversation configuration | v0.3.0 p95 | v0.3.1 candidate p95 | Change |
|---|---:|---:|---:|
| Native, 4,000 characters | 5.054 ms | 3.737 ms | −26.05% |
| Actual MCP stdio, 4,000 characters | 7.409 ms | 5.937 ms | −19.87% |
| Native, 512 tokens | 7.620 ms | 6.408 ms | −15.90% |
| Native, 1,024 tokens | 6.706 ms | 5.504 ms | −17.92% |
| Native, 2,048 tokens | 6.684 ms | 5.398 ms | −19.24% |

Token configurations use `cl100k_base` with an 8,000-character ceiling. All ten
pooled cells stay within the registered 5% p50/p95 regression limit. The
synthetic 512-token cell retains a **0.12% p95 regression**; individual rounds
and negative results remain in the report. These are retrieval measurements
against the previous Book implementation, with no generated-answer or
whole-product competitor-speed claim.

The implementation obtains a project's smallest/largest page rowids within
the existing read snapshot. When that span is at most half the archive's span,
bounded FTS iteration skips unrelated postings while keeping the exact scope
filters before the candidate limit. Other layouts retain the existing query
plan. The benefit depends on the workload and archive layout.

### Startup tradeoff retained

The public-conversation workers' mean time to open a new empty database rose
from **34.456 ms to 39.294 ms: +4.838 ms, or +14.04%**, across four samples per
engine. This correctly triggered the registered resource review. The original
automatic report remains `accepted: false`; the separate review accepts the
retrieval improvement with this startup exception disclosed. It found no new
operation in the measured constructor/schema path, but the original run did
not collect enough OS diagnostics to identify the specific timing cause.
This release makes no startup-speedup or universal startup non-regression claim.

## Current comparison

The authoritative [round-three comparison run](https://github.com/Afloat16/AI-Memory-Book/actions/runs/43267797247)
and its offline audit are **complete-verified**. All **4,608 native calls** and
**4,608 component searches** are preserved. The default candidate matches the
v0.3.0 complete non-timing payload in **1,536 native pairs** and **768 component
pairs**, with zero differences.

The same-host comparison uses 256 HotpotQA questions selected by the registered
ID rule after source/evaluator freezing, with zero overlap with either earlier
cohort. The table shows identical supplied pages, top five and common whole-page
packing within **1,024 `cl100k_base` tokens**. Quality uses each question's first
response; search latency uses three actual repetitions.

| Retrieval component | Evidence recall | Complete evidence | Packed-context MRR | Native search p95 |
|---|---:|---:|---:|---:|
| **Book — default lexical** | 76.28% | 52.34% | 0.8132 | **2.784 ms** |
| **Book — optional Q2** | 76.77% | 54.69% | 0.8239 | **11.226 ms** |
| claude-mem 15.18.1 — native FTS | 70.68% | 45.31% | 0.7674 | 22.484 ms |
| ai-memory v3.4.5 — local hybrid | 77.27% | 55.86% | 0.8182 | 27.545 ms |
| billion-context `9674cfa` — search kernel | **78.91%** | **58.20%** | **0.8277** | **0.793 ms** |

Book's default finds complete evidence **7.03 percentage points** more often
than claude-mem FTS in this setting; Q2's difference is **9.38 points**. Both
Book modes have lower measured search p95 than the claude-mem and ai-memory
components. **ai-memory has higher completeness than Q2; billion-context leads
the displayed recall, completeness, MRR and search timing.**

The timing boundaries differ: Book includes in-process Python context assembly;
claude-mem measures native SQLite/Bun search; ai-memory uses local hybrid
HTTP/MCP; billion-context measures its Node search kernel. The displayed native
search timings exclude the additional bridge overhead for claude-mem and
billion-context. Full per-query read costs, adapter timings, preparation, RSS,
storage, tokens and every budget are recorded separately. These measurements
do not establish whole-product speed ratios or generated-answer accuracy.
This is a new selection from the same public HotpotQA source, not a new domain;
the selection is regression data after this first scoring.

## Install and connect

Requires Python 3.10+ with SQLite FTS5. The release installer uses an isolated
environment and a universal wheel; the standard installation needs no Git,
Node.js or separate database server.

**macOS / Linux**

```bash
curl -fsSLo install-memory-book.sh https://raw.githubusercontent.com/Afloat16/AI-Memory-Book/v0.3.1/scripts/install.sh
bash install-memory-book.sh
```

**Windows PowerShell**

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/Afloat16/AI-Memory-Book/v0.3.1/scripts/install.py -OutFile install-memory-book.py
py -3 .\install-memory-book.py
```

Then connect a client and explicitly enable supported transcript capture:

```bash
memory-book setup --client claude-code --capture --background
memory-book doctor
```

Use the exact launcher path printed by the installer if it is not on PATH,
then restart the client. Replace `claude-code` with your supported profile;
omit `--capture` for MCP access alone. Host permissions and model tool
selection apply.

**Upgrade:** re-run the installer and your existing `setup` command so client
and background-service paths use the new environment. Existing memory and the
previous environment are retained. v0.3.0 archives keep the same schema and
source/index representation in this patch. Older-version migration and
rollback requirements remain in the
[upgrade guide](https://github.com/Afloat16/AI-Memory-Book/blob/v0.3.1/docs/deployment.md#upgrading).

## Validation and remaining limits

Publication requires the nine exact-commit CI jobs covering Python
3.10/3.12/3.13, actual MCP stdio, the browser reader, Linux/macOS/Windows
installers and container persistence. Release assets include wheel/source
distributions, installers, checksums and source/build provenance. The release
workflow appends its exact source commit and successful CI run to these notes.

The sole project-local-statistics quality candidate **is not shipped**. Its
original 8,082 calls and eight workers were recovered and audited without new
retrieval calls; it failed 14 registered loss checks. All gains, losses and
interrupted-upload evidence are retained. The earlier rejected novelty
experiments also remain closed. This patch's accepted optimization preserves
default quality rather than establishing a new quality gain.

Q2 still adds local model/index costs and can lose evidence at small budgets.
In the new native 512-token `o200k_base` setting with an 8,000-character ceiling,
complete evidence falls from **35.55% lexical to 33.20% Q2**. All individual
gains and losses remain in the final assessment.
When embedding Book in an application that imports ONNX Runtime first, set
`ORT_DISABLE_TELEMETRY=1` before starting that application; a later opt-out
cannot undo an earlier initialization event. See the
[semantic guide](https://github.com/Afloat16/AI-Memory-Book/blob/v0.3.1/docs/semantic-retrieval.md).

This remains an experimental local single-user project. Component interfaces
and cost boundaries differ; retrieval evidence scores are not final-answer
accuracy, and another selection from the same public source does not establish
cross-domain transfer. Client configuration fixtures do not certify every
vendor app or guarantee automatic invocation. The local archive is
unencrypted, and recalled evidence enters the AI client's model context.
