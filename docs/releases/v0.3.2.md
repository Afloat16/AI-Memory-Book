# v0.3.2 — Less token-budget work, the same source evidence

**Release preparation — unpublished.** The fixed C2 source has passed formal
performance acceptance. The fresh component comparison and final release
verification are pending; repository comparisons will use that completed run.

AI-Memory-Book gives AI clients a shared local archive of original conversations.
This experimental candidate reduces repeated source parsing and token counting
while preserving the existing retrieval policy, source addresses and budgets.

## Changes in the candidate

- **Defer unnecessary source parsing.** Capture original turns and source maps
  inside the existing database snapshot. Pages with an affirmative full-segment
  equality certificate need projection only when supplemental evidence is used;
  other maps retain the original eager corruption checks. Deferred work uses
  captured text and performs no later database reads.
- **Narrow projection and reuse accepted work.** Bisection skips source units
  outside a mapped segment while preserving containment and exact-text checks.
  Assembly retains the count for the last accepted context, including when a
  later candidate is rejected, and avoids a redundant private metadata copy.
- **Count certified citation boundaries once per call.** With tiktoken 0.12.0
  and the inspected `cl100k_base`/`o200k_base` patterns, sealed citation blocks
  can reuse exact counts. A strict UTF-8 byte bound can prove that a block fits;
  final `context_tokens` remains exact. Unsupported patterns, custom counters,
  unknown encoder origins and invalid boundaries keep the original full-context
  fallback, including its error behavior.

Global BM25, lexical normalization, ranking, scope filters, packing order,
source coordinates and MCP response formats retain their existing contracts.
Q2's model, vectors and fusion are unchanged. Schema 3 and dependency requirements
are unchanged; no persistent feature cache is added.

The rejected body-feature cache and proposed highlight-query specialization are
absent from C2. Earlier A/B/C1 sources, adverse results and interrupted attempts
remain preserved in the [round-four decision history](../optimization-round4.md).

## Verified compatibility

The completed [Q2 audit](https://github.com/Afloat16/AI-Memory-Book/blob/f8f1653c0653654ed574569fff1aaf4dbaeef6d1/benchmarks/reports/round4-compatibility-final/paired-audit.json)
verifies **1,968 calls and 984 matching complete non-latency payload pairs**
against published v0.3.1. It covers authored36 and historical Hotpot128, both
tokenizers and 512/1,024/2,048-token budgets. Baseline and candidate use identical
saved vectors. Recorded source, projection, scope, token and metadata errors
are zero.

These are previously scored regression cohorts. The audit checks recorded
payload hashes, vector/source identities and complete attempt ledgers without
repeating retrieval or inference; it does not establish new quality gains or
independently reconstruct omitted response bodies. Fresh artificial fixtures
cover rejected later blocks, nonmonotonic token counts, Unicode, custom encoders,
source corruption and concurrent writers.

## Completed formal performance

The sole registered hosted run was triggered from
[`f8f1653c0653654ed574569fff1aaf4dbaeef6d1`](https://github.com/Afloat16/AI-Memory-Book/blob/f8f1653c0653654ed574569fff1aaf4dbaeef6d1/benchmarks/experiments/round4-performance-binding.json).
Its completed matrix has **56,784 calls**, sixteen sequential workers, four
balanced rounds and twelve cohort/configuration cells, including actual SDK
MCP. Complete outputs and recorded invariants match. The original automatic
verdict is **accepted**, with no resource exception or gate change.

Across the twelve pooled cells, the geometric-mean p95 improvement is **10.13%**.
The following public-corpus cells each contain 4,060 samples per source:

| Configuration | v0.3.1 p95, ms | v0.3.2 p95, ms | Change |
|---|---:|---:|---:|
| Native, 4,000 characters | 2.361 | 2.199 | −6.89% |
| Actual SDK MCP, 4,000 characters | 3.468 | 3.518 | **+1.44%** |
| Native, 512 tokens | 3.794 | 3.070 | −19.07% |
| Native, 1,024 tokens | 3.200 | 2.611 | −18.41% |
| Native, 2,048 tokens | 3.130 | 2.560 | −18.20% |
| Actual SDK MCP, 1,024 tokens | 4.358 | 3.887 | −10.80% |

No pooled p50/p95 regression exceeds 5%. The largest registered resource mean
increase is **6.02%**, public token-MCP startup from 345.683 to 366.504 ms.
All round-level regressions and raw samples remain published. The aggregate
exceeds its 10% gate by only **0.1294 percentage points**; these descriptive
results establish neither statistical significance nor a universal speedup.
Returned text and output-token totals are unchanged, so this release does not
claim model-token savings from this optimization.

## Install or upgrade after publication

Requires **Python 3.10+ with SQLite FTS5**. The following URLs target v0.3.2 and
are not yet verified published assets.

**macOS / Linux**

```bash
curl -fsSLo install-memory-book.sh https://raw.githubusercontent.com/Afloat16/AI-Memory-Book/v0.3.2/scripts/install.sh
bash install-memory-book.sh
```

**Windows PowerShell**

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/Afloat16/AI-Memory-Book/v0.3.2/scripts/install.py -OutFile install-memory-book.py
py -3 .\install-memory-book.py
```

Connect a client and explicitly enable supported transcript capture if wanted:

```bash
memory-book setup --client claude-code --capture --background
memory-book doctor
```

Use the launcher's full path if it is not on PATH, then restart the client.
Omit `--capture` for MCP access alone. To upgrade, rerun the installer and setup
with the same database/configuration, then update an existing background service.
The archive and previous environment are retained. See the
[deployment and upgrade guide](../deployment.md#upgrading) for schema history,
rollback requirements and alternative installation methods.
