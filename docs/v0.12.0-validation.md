## Runtime changes

Current-state temporal ordering authenticates complete original turns before
comparing declared fields. Statement-local qualifiers now apply to candidates
inside the original relevance pool as well as newly added candidates. Another
sentence, another field, a user question or a directory title cannot supply a
missing production/staging qualifier. Unclassified statements do not receive a
relevance transfer merely for being newer.

The parser supports bounded numeric prose and complete Chinese withdrawal
statements with explicit guards for causal clauses. It rejects the inspected
staging-only and pending-approval suffix counterexamples. Standalone reporting
labels are recognized without erasing environment names. These rules remain
conservative syntax checks; they cannot determine a speaker's authority or
resolve general natural-language contradictions.

The character allocator can complete short pages of at most 240 characters by
redistributing allowance above the existing minimum from longer truncated
pages. It keeps candidate order, citation framing and already complete pages.
Authenticated current-turn spans cannot donate their necessary allowance.
Exact-token assembly starts from these actual character blocks, preserves every
whole block that first-fit can accept and then uses the existing supplementation
units. Character and token paths therefore share the protected starting blocks;
the earlier first candidate's unchanged-token-allocation claim does not describe
this accepted source.

## Short-page and token preservation

The unchanged guard evaluator runs actual production recall at two short-record
sizes and budgets from 400 through 1,600 characters in steps of five. Each
backend executes **482 configurations**, totaling 964 new requests.

| Outcome, per backend | Result |
|---|---:|
| Configurations | 482 |
| Recorded original controls containing current evidence | 434 |
| Candidate configurations containing that current evidence | 434 |
| Previously present controls lost | 0 |
| Original unprotected-candidate regressions | 34 |
| Those original regressions recovered | 34/34 |

This is **not 482/482 answer completeness**: 48 tight-budget controls originally
lacked the current evidence and still do. These are configurations of one
authored fixture, not independent questions. Only the 34 original regressions
have complete prior response payloads, independently verified by the guard;
the other 448 original configurations retain presence observations only. No
missing original payload was reconstructed.

Every new response and original-page follow-up is retained. Independent audits
check full matrices, request identities, coordinates, project scope, budgets,
source/evaluator/native-binary stability and raw/compressed hashes. All 482
Python/native guard response pairs agree after excluding only latency.

The original full-suite failures also exposed a character/token legacy-block
mismatch. The corrected source starts exact-token first-fit from the protected
character allocation and passes the unchanged core/token preservation assertions.
The old token timings remain historical; this is not a new token-path speedup.

## Directory and project scope

119/119 authored contracts, makes 130 locator calls and 161 complete original-page
reads covering 80 distinct pages, and retains 597 operation rows. These are the
same 119 contracts on two implementations, not 238 independent cases or an
answer-accuracy test.

The offline audit independently reconstructs original turns, checks each
request's project boundary and returned coordinates, validates chapter pagination
and checks source inventories against the accepted commit. Separate ingestion
times cause 97 chapter `updated_at` values to differ between backend runs; other
saved fields agree. Original timestamps remain in the raw records. The original
v1 fixture correction remains disclosed in the earlier validation record.

Project-bound MCP connections inherit an exact project when omitted and reject
conflicting projects or foreign source IDs. This guards accidental scope changes
within that connection; it is not multi-user authentication or automatic current
working-directory detection. Unbound searches can intentionally span books.
