# 架构与数据语义

## 目标

组织结构与读取执行顺序分开设计。目录解决“记忆在哪里”和“上下文怎样组织”；默认查询不需要模型逐层选择分支。一次 `recall` 就返回相关原文、可寻址页 ID、来源和读取统计。

核心不生成答案，不调用 LLM，不把摘要当作原文，也不承诺所有语义改写都能被词法索引找到。

## 写入路径

1. 校验一条规范化会话：项目、稳定会话 ID、可选任务 ID、来源时间和文本消息。
2. 在用户消息边界组装 turn；一个 turn 包含一次用户提问及下一次用户提问之前的回答/文本工具消息。前置 system/developer 消息保存在源 JSON 中，不自动变成检索指令。
3. 自适应分节根据长度、问题词面相似度和常见追问开头分组，最多合并四个 turn。超过页上限的单个 turn 按段落/换行优先切分，必要时硬切，不丢弃字符。
4. 在一个 SQLite 写事务中保存规范化源会话、turn、section、page、FTS 索引和抽取式目录概览。
5. 递增全库 revision，删除旧查询缓存。任何索引写入失败会回滚源会话与派生记录。

默认参数是 `max_page_chars=900`、`min_page_chars=400`、`similarity_threshold=0.12`。这些是开发集选择的工程参数，不是语言学意义上的正确章节边界。小于下限的相邻短问答可能合并；较长文本遇到话题变化则分开。默认配置可以通过 Python API 调整，CLI 暴露模式和页上限。

## 数据对象

| 表 | 用途 |
|---|---|
| `projects` | 显式项目 namespace 和显示名 |
| `chapters` | 项目内的显式任务，或没有任务 ID 时的独立会话章 |
| `sessions` | 规范化源 JSON、来源/导入时间、内容哈希、分节配置 |
| `turns` | 提问与后续消息的完整文本，以及原消息编号 |
| `sections` | 连续问答分组和抽取式问题概览 |
| `pages` | 内容相关地址、页正文和精确来源区间 |
| `pages_fts` | 预分词后的标题、问题提示、正文和目录名称 |
| `recall_cache` | 查询参数哈希、revision、序列化结果和有限缓存条目 |
| `meta` | 全局 revision |

数据库带 SQLite `application_id` 和 `user_version`。v0.1 的 schema 为 2；能迁移本项目早期开发 schema 1，保留已有页地址、补齐源时间并重建词法索引，拒绝初始化已有其他应用表的数据库。开发 schema 1 没有保存自定义分页上限，迁移保留实际已有页，后续 link 使用当时的默认上限 1800；若原来有自定义参数，应按原参数重新导入。FTS5 是运行前提，不会悄悄改用全表扫描。

`project + session_id` 决定源会话身份。无 `created_at` 时首次写入产生的时间会进入源 JSON，后续导入和导出保持该时间。用户显式提供的项目名/任务名可以更新显示名；省略名称不会把已有友好名称覆盖成 ID。

跨会话任务使用显式 `task_id`。`link_session` 调整任务归属时复用原分节配置；未改变的页正文和页地址保持一致。当前不是自动跨会话语义聚类系统。

## 读取路径

FTS5 使用预分词文本：英文/标识符拆词、Unicode 正规化和重音折叠、中文连续字符 bigram。查询里的 FTS 操作符不会直接执行，SQL 参数也不会拼接用户值。

检索按以下顺序完成：

1. 用完整查询参数和 revision 检查有界持久化缓存。
2. 在同一个读快照中执行 FTS BM25，项目/任务/会话过滤在候选截断前生效。正文必须存在词法命中，只有目录名命中不能被当作证据。
3. 最多获得 96 个候选的元数据。`flat` 使用基础排名；`book` 在相同候选集上加入小幅目录标题重叠加权，不硬裁剪其他章节。
4. 只加载排名靠前的原文页。在字符预算内使用所有基线共用的查询居中摘录器，打包引用标题与证据。
5. 写缓存前再次核对 revision，避免并发导入后把旧结果重新写回缓存。

目录加权是一个可独立关闭的实验因素，并没有因“树结构”而获得优越性保证。BM25 和 tokenization 的背景见 [SQLite FTS5 官方文档](https://www.sqlite.org/fts5.html)。

## 来源字段

返回结果的 `source_refs` 指向**原始规范化会话**，而不是摘要猜测出的出处。

| 字段 | 语义 |
|---|---|
| `project` | 原项目 ID |
| `session_id` | 外部稳定会话 ID |
| `turn_index` | 从 0 开始的用户提问/turn 编号 |
| `message_indices` | 源 `messages` 数组的消息编号 |
| `start`, `end` | 本次返回内容在完整页正文中的半开字符区间 |
| `turn_start`, `turn_end` | 同一段在组装后的完整 turn 文本中的半开字符区间 |
| `created_at` | 源会话时间 |

turn 文本包含 `USER:`、`ASSISTANT:` 等角色标签，区间基于这个可重建的文本。不是原 JSON 文件字节偏移。`excerpt_spans` 表示摘录对应的页区间；显示省略号不属于原文区间。

页 ID 包含来源身份、位置与正文哈希。修改正文后旧页地址失效，读取返回 not found，不会静默把旧引用解释为新内容。原始规范化会话可通过 `get_session`、CLI `source` 或 JSON 导出恢复。

## 预算与分页

`context_chars == len(context) <= budget_chars`。这里使用 Python Unicode 字符计数，不是 UTF-8 字节数。引用标题和来源时间算入 context。较小预算可能连一个包含出处的证据块都容纳不下，此时返回空 context 和原因。

Python API 返回 `context` 和结构化 `results`，便于应用渲染。MCP 特别压缩为单份 JSON 文本，去掉 `results` 中重复的证据文本与路径，不同时发送 `structuredContent`。来源 JSON 等元数据仍会增加响应体积，所以不能把 context 预算写成整个模型输入的精确上限。

目录的章、节、页分别分页：`toc`、`chapter`、`section`。章节中每个小节默认只预览 20 页，剩余页通过 `pages_next_offset` 继续。正文 `read` 也支持字符偏移分页。Markdown 导出会遍历全部分页。

## 缓存、并发与删除

缓存默认最多 128 条，全库 revision 失效机制优先保证正确性；一个项目更新也会清掉其他项目的缓存，这是简单性和缓存命中率的取舍。当前淘汰按写入时间，不声称是精确 LRU。

SQLite WAL 和 busy timeout 支持多个本地连接。一个 `MemoryBook` 实例不跨线程共享；网页/MCP 每次调用使用独立连接。源会话更新采用整会话替换事务，而非只重建单个追加 turn，因此非常长的会话频繁重复导入仍有写入成本。

删除会话/项目时，外键级联移除派生行，FTS 删除触发器移除索引，再同步清空缓存。CLI 删除要求明确 `--yes`；默认 MCP 只读，也没有 MCP 删除工具。删除不提供内建回收站，应先导出需要保留的数据。

## 运行边界

本地阅读服务只允许 loopback 地址，校验 Host；写入额外要求同源 Origin 和每启动随机 token。页面只用文本节点展示历史内容，不执行其中的 HTML。服务不作为公网多用户应用使用。

历史中互相矛盾的决定不会自动合成“唯一真相”。最新状态类查询会提示检查来源时间。低词面重叠、隐含关系或需要外部知识的问题是当前词法版本的明确边界。下一阶段可研究可选语义候选与事实版本关系，但必须保留原文兜底和对照实验。
