# v0.5.0 engineering validation

The v0.5.0 source adds explicit recall intent, import preflight validation and
consistent book exports. On the unchanged engineering development workload,
Book retrieves complete evidence for **72/72 answerable questions** and passes
**48/48 fixed-policy cases** at the default **2400-character** budget in both
the native and common whole-block tracks. Neither track has a stale-only case
at that budget.

The smaller budget exposes a material tradeoff. At **1200 characters**, native
Book improves to **68/72** complete cases, but common whole-block Book regresses
from **58/72 to 52/72**, with policy passes falling **34/48 to 28/48** and
stale-only cases rising **6 to 12**. The pinned billion-context component has
**64/72** complete cases and **40/48** policy passes at that same whole-block
budget. The default-budget improvement does not establish an advantage at
every budget or with every packer.

All counts below come from the [retained reports and raw responses](../benchmarks/reports/v0.5.0-engineering/),
with case-by-case changes in [comparison.json](../benchmarks/reports/v0.5.0-engineering/comparison.json).
These are synthetic development diagnostics, not an independent holdout,
LLM-generated code accuracy, a productivity measurement or a full-product
comparison. This document records source validation; publication and packaging
verification must be recorded separately after their release gates complete.

## Engineering behavior exercised

### Explicit and automatic temporal intent

Python, CLI, MCP and local HTTP recall accept `temporal="auto"`, `"current"` or
`"relevance"`. The default auto resolver distinguishes requests to cite original
evidence and dataset labels such as `dataset 2026` from historical/as-of
references. Comparisons, negated current requests with historical wording and
other ambiguous current/historical combinations retain conservative relevance
ordering. The original query and archived text are not rewritten.

An explicit mode lets an algorithm pipeline or agent state its intent without
depending on those wording rules. Modes have separate cache keys. Python, CLI
JSON, HTTP and MCP `details=true` responses explain the requested mode, effective
mode, basis and relevant lexical cues. Compact MCP output retains its existing
projection. `flat` remains the relevance baseline; combining it with explicit
`current` fails clearly instead of silently ignoring the request.

Current ordering is applied again after optional semantic candidate fusion,
within the same bounded pool and source snapshot. Comparability still requires
the same task and a nonempty identical exact-term match set. Similar embeddings
alone cannot establish a factual revision. Event-count queries retain repeated
occurrences. Relevance is not an oldest-first or as-of-date solver, and current
ordering does not determine which source is authoritative. The
[14 temporal regression methods](../tests/test_temporal_recall.py) cover mode
overrides, ambiguous wording, invalid types, caches, scope, both real tokenizers,
semantic routing, CLI, HTTP and real MCP stdio. Fixed semantic candidate fixtures
check ordering and interface behavior; they do not measure embedding quality.

### Validate import batches before opening the archive

CLI import now parses and validates every input session before opening or
migrating the database. Tests place an invalid timestamp, field, NUL, oversized
input or unpaired Unicode surrogate after an otherwise valid replacement and
verify that the earlier stored session is unchanged. Invalid input also leaves
a missing database absent and an older-schema archive unmigrated. Errors identify
the source file and session position. UTF-8 validation applies to direct Python
and MCP ingestion as well.

Omitted project/task names and creation times retain their normal inheritance
behavior, and unchanged retries remain idempotent. This is validation before
writes, not a new transaction spanning the entire batch: a disk or runtime
write failure can still leave earlier valid sessions committed. The
[import preflight tests](../tests/test_import_preflight.py) retain these boundaries.

### Publish complete exports from one snapshot

`export-book` reads the index, paginated pages and source JSON from one SQLite
snapshot, even while another connection commits updates. It assembles the
complete output in a sibling staging directory, then publishes the result.
Injected read, write and publication failures verify snapshot release, staging
cleanup, destination preservation and retry behavior. A caller's active
transaction is rejected without being committed or rolled back.

Nonempty destinations, files, symlinks, Windows junctions and the current working
directory itself are rejected. POSIX publication uses atomic directory rename.
On Windows, publishing over an existing empty directory requires removing that
directory first; the destination can briefly be absent. Complete-output
visibility is not a power-loss durability guarantee. See the
[export regression cases](../tests/test_export_book.py); the Windows-specific
junction test is not exercised by the local Linux run.

The source also includes the previously validated schema-4 lexical indexes,
identifier aliases, token-only correction handling, online backup and read-only
database checks. Their earlier measurements remain in the
[retained source report](developer-engineering-validation.md); they are not
presented as newly measured improvements in this iteration.

## Workload and metric definitions

The unchanged workload has **eight projects, six chronological checkpoints and
80 questions**: **72 answerable cases**, **80 required evidence spans**, **48
fixed-policy consumers** and **eight missing-evidence questions**. Each query sees
only the history available at its checkpoint, with the requested project scope.
It covers routing, ranking, training-data splits and attention constraints,
including failed attempts, replacements, identifiers, bilingual wording,
long gaps and historical decisions.

Evidence recall counts required quotes surviving both the returned context and
the cited original source slice. Complete evidence requires every required span
for an answerable case. A fixed consumer extracts a policy and runs handwritten
algorithm variants; its pass rate is not generated-code accuracy. Stale-only
means obsolete evidence is present while required evidence is absent. Old and
current evidence can legitimately coexist, so stale-only is reported separately.

Budgets include citations and separators and are measured in **characters**,
not model tokens. Three repetitions provide timing samples, not three independent
quality observations. Result caching is disabled; SQLite, filesystem and process
caches are not reset between every call.

## Track B: actual open-source component with common whole-block packing

The actual [billion-context](https://github.com/ranxianglei/billion-context) /
[acp-kernel](https://github.com/ranxianglei/acp-kernel) search implementation is
pinned to [`9674cfaf`](https://github.com/ranxianglei/billion-context/tree/9674cfafbc78c50245ae0d887483d3d6ce880c15).
Locked original files are digest-verified before Node erases TypeScript syntax;
the ranker is not reimplemented. Its license includes MIT text and an additional
product-surface attribution condition, recorded in the
[component binding](../benchmarks/reports/v0.5.0-engineering/current-components/binding.json).

Both engines receive the same complete source-page bodies, project filter and
top-five limit. A common packer preserves native candidate order and **skips
whole blocks that do not fit**; it never uses native excerpts or truncates a
body. Book retains hierarchy/FTS metadata, while Billion receives uniform
assistant-role messages containing supplied title/body/project fields. Shared
pages and packing do not imply identical indexed features or a full-product
comparison. This track must not be mixed with native excerpt results.

previous Book source, the two bilingual training cases improve, with no complete

At 1200 characters, Book has **eight paired wins and twenty losses** against the
component, and **six losses with no gains** against its own previous source.
The six newly regressed cases are the bilingual routing, ranking and attention

One concrete example is `m4:routing-online:chinese`. The previous whole-block

The common packer omits the replacement block, then admits the smaller old

consumer fails one of three checks. The raw response records the omitted page
ID, so the failure can be traced to candidate order plus whole-block packing.
Native excerpts at the same budget can still retain the needed decision.

The full 1200-character whole-block failure set contains two training replacement
cases, eight multiple-constraint cases, eight bilingual cases and two training

in this comparison; these results make no numerical claim against them.

## Defaults, integrity and timing boundaries

The [default-profile check](../benchmarks/reports/v0.5.0-engineering/default-profile/report.json)
executes **160 calls** over all 80 questions. All 80 default responses equal
explicit 2400-character/five-result calls and this iteration's saved explicit
replay, excluding only `latency_ms`. Scores, source references, warnings and
temporal diagnostics remain part of equality. The unchanged verifier has fields
named `historical` and `frozen`; [reference.json](../benchmarks/reports/v0.5.0-engineering/default-profile/reference.json)
identifies their actual target as this same-runtime replay, not an earlier
release's output. The verifier source was not edited.

Both tracks report zero source-validation errors, zero character-budget
violations and zero output changes across the three repetitions. All eight
missing-evidence queries nevertheless return related context for Book and the
component. A nonempty context does not demonstrate a wrong generated answer,
but these results also do not establish reliable abstention or absence detection.

Native Book at 2400 characters records retrieval p50 **2.036 ms** and p95
**7.059 ms** over 240 calls; at 1200 it records **3.115 ms / 10.771 ms**. These
are local measurements around retrieval/context construction, excluding import,
scoring, fixed-consumer execution and model generation. Before/after runs were
not an isolated counterbalanced performance experiment, so their timing delta
is not a validated speedup or slowdown.

Component Book timing includes its native context assembly. Billion reports
search-kernel time separately from the persistent JSON process roundtrip. The
common packer operates on supplied in-memory pages and does not measure
Billion's host decompression or native follow-up reads. Native search results
are reused across both budgets; those timing samples are not independent by
budget. Processes restart at each chronological checkpoint. These boundaries
cannot establish a whole-product speed ratio, model cost, coding time or time
to a correct patch.

## Retained evidence and reproduction

[compression-manifest.json](../benchmarks/reports/v0.5.0-engineering/compression-manifest.json)
records original and stored sizes and SHA-256 values for the native raw JSONL,
component raw JSONL, complete component native traces and all three test logs. Gzip storage is
lossless. `comparison.json` binds the current and previous compressed inputs by
digest; datasets, checkpoint page bundles and individual source references are
retained alongside them. No failed cases are removed from the record.

Use a committed checkout with the required optional test dependencies, including
the real MCP SDK, tiktoken, tomlkit, NumPy and PyArrow. The complete local test
count is environment-specific. Use an absolute Python interpreter path without
`..` for provenance-sensitive subprocess checks, and a shared absolute
`TIKTOKEN_CACHE_DIR`; prewarm `cl100k_base` and `o200k_base` if their public
vocabularies are not already cached. From the repository root:

```bash
export PYTHONPATH="$PWD/src"
python -m unittest discover -s tests -v
python -m benchmarks.engineering_workflow --output ./validation/native --repeats 3 --budget-chars 1200 2400
python -m benchmarks.engineering_components --output ./validation/components --repeats 3 --budget-chars 1200 2400 --cache ./validation/billion-source
```

The [component runner](../benchmarks/engineering_components.py) requires Node
24+ and the digest-locked upstream source. Its command above fetches missing
public source files; add `--offline` only after the cache contains every locked
file. The retained run used offline mode. Choose fresh output directories;
existing nonempty results are deliberately rejected.

To repeat the same-runtime default comparison without changing the historical
verifier or any frozen fixture, explicitly select the new native replay:

```python
import gzip
from pathlib import Path
from scripts import verify_engineering_defaults as verifier

reference = Path("validation/native").resolve()
raw = reference / "raw.jsonl"
(reference / "raw.jsonl.gz").write_bytes(gzip.compress(raw.read_bytes(), mtime=0))
verifier.FROZEN = reference
verifier.verify(Path("validation/default-profile"))
```

This exercises the existing `verify()` function with a selected reference; it
does not turn the already-seen workload into an independent evaluation. No
private conversation corpus, model endpoint or model API credentials are needed
for the two engineering replays. Publication still requires the exact-commit
release gates described in the [release record](releases/v0.5.0.md).
